# Client 端设计

Client 是客机进程，运行完整的以撒游戏与 REPENTOGON，但不运行玩法逻辑。它做四件事：上传本机输入；接收并校验 Host 的状态；在主线程把状态写进本地原生对象；交给原生代码完成显示。本文按这四个阶段说明，最后介绍插值与预测、副作用隔离和扩展方法。

线格式与确认见[同步](synchronization.md)，Host 一侧见 [Host 端设计](host.md)。

## 1. 原则

- **不跑玩法**：拦截 `Game::Update`、`Room::Update`、`EntityList::Update`、`Entity_Player::Update` 等玩法入口；玩法随机数、存档、成就和解锁一律不在客机产生。
- **原生显示**：把 Host 的状态写进本地原生对象，再调用原生 `Game::Render`。客机不自行实现绘制。
- **一帧内直接应用**：在 Manager 边界一次调用内完成整帧写入，不跨帧准备，也不建离线副本。
- **写前校验**：解码和纯值校验在连接线程完成；主线程只核对目标对象仍存活，指针、容器、资源字段走具名原生写入器。
- **按对象隔离失败**：单个对象写入失败只跳过它，下一帧重试；达到阈值才请求完整基线，期间继续显示当前画面。

## 2. 会话

### 2.1 连接

| 命令 | 作用 |
| --- | --- |
| `cs client <地址> <端口> <设备键>` | 以客机身份连接 Host |
| `cs lobby_join <地址> <端口> <设备键>` | 加入 Host 的大厅 |
| `cs lobby_role`、`cs lobby_ready` | 大厅中选角、准备。只能选房主存档已解锁的角色，解锁位图随名单下发 |
| `cs stop` | 离开会话 |

客机只在稳定的菜单状态接管，不在本机创建玩家，也不载入本机的 Continue 存档。世界由 Host 的完整基线在本地构建。

握手在 Ready 之前比较启用 Mod、版本、声明文本和内容 ID。启用了未声明的 Lua Mod、声明版本不受支持或清单不匹配时，大厅显示首个拒绝原因。会话内 Lua 热重载触发退休。

### 2.2 连接线程

`net/live.cpp` 的 `live::Client` 为每个连接起一条线程，负责收发包、握手、名单、输入上行和状态接收（第 4 节）。它与主线程之间只交换自有纯值：

- 主线程 → 连接线程：输入意图、应用完成回执、资源完成回执、恢复请求；
- 连接线程 → 主线程：控制事件、已封存的安装批次（邮箱）、资源装载任务、链路质量（RTT、丢包率，仅用于 HUD 显示）。

## 3. 输入上行

`game/client/session/client.cpp`：

1. **采样**：每帧在原生输入泵之后采样本机物理输入，转换为统一输入 `InputStateDraftV2`。冻结清单中的扩展键共同进入同一条命令。
2. **目标 tick**：用 Host 实际提交 tick 与本机单调时间的差值估计 Host 节拍，把命令投影到预计抵达 Host 的 tick。暂停或换代时立即丢弃旧估计。
3. **发送**：
   - 目标前进时，为跳过的每个 tick 各发一条同一采样的命令（有上限），边沿只放在最后一条；
   - 目标未前进但本帧移动、瞄准或按住位变了，以更高序号对同一目标重发一次（Host 取该 tick 最高序号的命令），重发不带边沿。
4. **阻断**：窗口失焦、本地控制台或暂停菜单打开时，本机输入封为中性；显示仍继续消费 Host 状态。

## 4. 接收

`state/client_receive.*` 的 `ClientStateReceiver` 在连接线程上串行处理状态消息：

1. **定界与解码**：先核公共头、作用域和整帧边界（`InspectStateFrame`），再逐记录解码（`DecodeStateFrame`），全程受访问预算限制。
2. **表**：合并成员目录增量（`state/client_tables.*`）；资源表到达后排入资源装载任务。
3. **影子状态**：把解码结果写入影子状态（`state/client_shadow.*`）。平铺记录在影子里保存成员的完整镜像，收到的变化字段覆盖进镜像（`state/client_flat.*`）；块记录的每个块独立拥有字节。World 的 Mod 段按冻结声明校验并累计成不可变 `ModShadowRef`，随同一应用票据投递。读原生影子值时，平铺记录用 `FlatValue(字段名)`，块记录用 `Field(字段号)`。
4. **校验**：对影子值做具名域校验和资源闭包检查（`state/client_validation.*`），不涉及原生地址。
5. **保留与 ACK**：把结果保留进快照环（深度 8），立即发送 AppliedAck。ACK 与主线程是否装好无关。
6. **安装描述**：在后台为本帧生成纯数字的安装描述（`ClientStatePreparation::PrepareStep`），连同候选、事件和票据封成 `ClientStateApplyBatch`。
7. **投递**：放进主线程邮箱。邮箱有两个通道：通道 0 是 World、联合帧和恢复批，通道 1 是普通 Body；总共两张票。旧的未应用 World 被更新的 World 取代。

资源装载任务（`ClientStateResourceJob`）按依赖闭包的拓扑顺序交给主线程，最多 8 个在途，在主线程空闲预算内用本机游戏文件装载 ANM2、图像和音效。

## 5. 原生安装

### 5.1 入口

主线程每次 `Manager::Update` 在 Manager 边界调用 `ClientBinaryScene::Pump`（`game/client/scene/client_binary_scene.cpp`）：收回上一轮回执、取新批次、执行安装，再把完成结果交还连接线程。

### 5.2 一次 World 安装

1. **选帧**：取邮箱中最新的 World，更旧的未应用帧直接丢弃。
2. **捕获旧画面**：换房时，在删除第一个旧成员之前捕获旧房间画面，供原生转场使用。
3. **删除**：本地存在但新帧中已离开的成员，经 Remove、ClearReferences、摘出受管列表并清 valid 后归还池槽。Player 和 Grid 各走自己的释放链。
4. **身份核对**：成员身份已有本地对象时，核对地址、实例代次和 type／variant／subtype：
   - 一致：转第 7 步写字段；
   - 形态前进且类型支持原生 Morph（拾取物、NPC）：原地 Morph，对象地址、引用和渲染顺序都不变；
   - 其他不一致：删掉重建。
5. **新建**：在 Init 隔离作用域里取池槽、执行原生 Init，使用 Host 的 InitSeed。池满时先回收，仍满则按优先级跳过（可缺的玩家泪弹最先跳过），下一帧再试。
6. **清理 Init 附属实体**：按隔离 Init 前后的池占用差集，删除 Init 顺带生成、但不在快照里的实体。
7. **写字段**：
   - 平铺记录按写入组从镜像写回（`client_flat_install.cpp`）：同一实例上一批写过时，只写包含变化字段的写入组；新建、完整基线、失败后补写、写入见证不符，以及每 32 份轮转命中时全量写入。块记录同一实例上一批写过时只写变化的块，其余情况写全部字段；
   - 纯值直接复制；
   - 指针、容器、资源和其他特殊语义走具名原生写入器（`client_atomic_install*`、`client_atomic_bindings*`、`client_field_staging*`）；容器可以在原承载上变长，写元素前重新定位；
   - 资源未就绪的对象延后，标记为待重写。
8. **挂引用**：Parent、Child、Target、Spawner 等引用按成员身份解析。目标缺席时清空引用槽、保留完整目标键，目标出现后补挂。
9. **全局状态**：写入 Game、Room、Level；写入内联显示标量的 Host 当前值（震屏、颜色、闪电、暗度、fade、水色等）、转场字段、paused 位和终结分支；按帧号方案 B 把 `Game+0x25A70` 写成帧头的 `game_frame`；写入不可算的注入值（优先原生 setter 或 REPENTOGON API，其次直接写内存）。
10. **事件回放**：按序号回放音效、横幅文字等外观事件，只在原生回放成功后推进水位，同一事件只播放一次。
11. **发布与回执**：发布本批，记录对象失败，回报完成结果。

整个过程在一次调用内完成，不跨帧，正式路径也不读回核对。Body 批次走同样的写入路径，只覆盖玩家身体的快变字段。

### 5.3 快速路径

静止或少量变化的场景，大部分记录相对上一批完全相同。为此有两层优化：

- **整批快速帧**：本批只含 World、结构与上一批完全相同、所有对象仍是同一实例时，跳过准备和描述，直接在当前安装器上执行“成员写程序”，全量写纯值叶并换上新计划。
- **吸收与静止记录**：不满足整批条件时，结构不变的 Entity／Grid 记录不生成纯值指令和可跳过的委托，由写程序在纯值段末尾统一写入。
- **强制刷新**：每 32 份 World 至少执行一次不吸收的完整事务，让具名写入器和漂移扫描覆盖全部记录。

快速路径的资格在任何写入之前判定，不满足就走普通路径，并记录首个原因（诊断计数 `FastMiss`）。

快速路径只作用于块记录（`client_atomic_install.cpp` 中平铺记录直接跳过成员写程序）。平铺记录本身已按写入组只写变化部分，不经过这两层优化。

### 5.4 失败与漂移

- 构造、Init、字段定位、容器和具名写入器失败时，记录成员键、实例和首因。已开始写入的对象先拆边和附件，再摘表、释放；其余成员继续同帧应用，下一帧重建缺席成员。
- 同一成员原生失败 3 次，或连续池满 30 帧，在本批回执处理完后请求完整基线（Resync Apply），当前画面继续显示。
- 放行的原生显示代码可能改写已同步的字段。滚动漂移扫描发现不一致时，把该记录标为待重写，下一份适用帧写全该根。

### 5.5 Mod 安装与通知

`ClientBinaryScene::InstallMods` 在 `Pump` 之后、显示推进之前使用已经发布的同一份 World。原生拆除前发实体移除通知，安装后按 global、player、entity 的顺序写 Lua；新建、重建的实体从影子读取当前值。批末派发实体安装、状态变更和场景启动通知。正常更新只写需要变化的记录，完整基线重写已同步值。setter 单条出错时保留上次成功引用，等待合法的新值或基线。D6 诊断模式每批以已安装字节重写并报告可观察的改写。意图结果在本轮应用后回到发起端。

## 6. 显示委托

### 6.1 拦截与放行

客机的每个 `client` 组 Hook 在进入时调用 `ClientDispatchBefore`（`game/common/bridge.h`），得到三种决定之一：

- **CallOriginal**：放行原生代码；
- **ExpectedSkip**：预期跳过，例如 `Game::Update` 在客机上永远跳过；
- **FaultSkip**：资格不符，跳过并记录。

放行由“根用途”授权：只有在 `ClientDispatchScope` 声明的根入口内，已登记的嵌套原生调用才被放行。这样原生显示树能正常运行，玩法更新则不会被意外调用。

### 6.2 显示推进

`Game::Update` 不运行，客机改在 Manager 边界、World 安装之后运行“显示推进”根（`ClientScene::AdvanceDisplay` → `ClientDisplayAdvance`，`game/client/display/client_display_native.cpp`），只调用已核实的显示子更新：

- HUD、小地图、相机、FX 层、排序、背景；
- 音乐 tick 和 SFX 刷新；
- 本地暂停菜单和光标。

显示推进按原生节奏：本机偶数 Manager 帧运行约 30Hz 的显示批次，每个 Manager 帧运行相机阶段。

### 6.3 绘制

包装原生 `Game::Render`。`ClientScene::BeginNativeRender` 进入时，由运动覆盖层把显示位置写进对象；`EndNativeRender` 退出时写回权威值。原生代码绘制房间、实体、HUD、地图和菜单。

### 6.4 具体约定

| 内容 | 做法 |
| --- | --- |
| 切房 | 原生转场。转场字段（mode、counter、progress、direction 等）同步 Host 当前值；客机不运行转场状态机，只捕获旧／新画面并调用原生 Render |
| 暂停 | `Game::IsPaused` 的原生调用者得到 Host 同步的 paused 位 |
| Projectile 显示偏移 | 绘制作用域内保存并精确恢复已同步的 PositionOffset `+0x350` |
| 地图拾取图标 | 在地图缓存构建 `0x9635B0` 作用域内临时镜像 Host 摘要合成的最小条目，调用后恢复 |
| 当前房间 SpawnSeed | 同步该 u32，原生 Render 在房间年龄 30 时会读它 |
| 外观随机 | 绘制随机、粒子等纯外观差异可以接受；影响布局或规则的结果仍同步 |
| 本地暂停菜单 | 原版 PauseScreen 在客机本地打开，Host 世界不暂停；选“退出”时离开会话 |
| Player 及楼层显示 | 使用同一 World 的自定义缓存、强制隐身、已采到的健康和充能查询结果、Boss 血条和当前楼层名称 |
| Mod 过场 | World 事件触发本地原生播放；清场请求在场景退休后播放，同序号的可靠 Retire 交付会去重 |

## 7. 插值、外推与预测

`game/client/presentation/` 的运动覆盖层只改显示，不进入协商或线格式：

| 阶段 | 内容 | 配置项（`isaac-cs/config.json` 的 `motion`） |
| --- | --- | --- |
| 远端插值 | 远端对象按带延迟的世界显示时间在两个样本间插值 | `interpolation` |
| 外推 | 样本断档时按速度外推 | `extrapolation` |
| 本机身体预测 | 用已发送但 Host 尚未确认的输入重放本机身体移动。速度模型和格子碰撞按 J273 逆向结果在 C++ 中复刻，不调用原生移动函数；Host 通过 Body 的 `predict_gate` 告知是否允许预测 | `prediction` |
| 本机泪弹出生融合 | 本机身体发出的泪弹出生时带上与预测身体位置的偏移，约 150 ms 内线性衰减到 0；偏移超过 3 格（如传送）不融合 | `tear_birth` |
| 敌弹前推 | 本机正在预测时，敌方弹幕单独外推到预测时间，外推上限 500 ms | `projectile_lead`（默认关） |

生命周期：每次 World／Body 发布后采样权威值（`Installed`）→ 每次显示推进求显示值（`Prepare`）→ 相机阶段和 `Game::Render` 各一对 `Enter`／`Exit`，写入显示值后写回权威值。换房、换路由或新连接时作废全部历史。

## 8. 副作用隔离

| 类别 | 做法 |
| --- | --- |
| 玩法更新 | 拦截 Game、Room、EntityList、Player、Door 等更新入口 |
| 随机数 | `runtime_random_hooks` 拦截 CRT `rand`、REPENTOGON `RandomFloat`、Lua `math.random`；原生 RNG 构造与推进也在 Hook 下，不得改变 Host 已同步的结果 |
| 持久化 | 拦截存档读写、游戏状态保存、成就、图鉴、挑战与 Steam 解锁（`gamestate_*`、`manager_save_game_state`、`pgd_*` 等）。客机公开 PGD 查询读取 Host 的同步镜像，Lua 写入公开入口和原生写入都有保护 |
| Lua 回调 | 按注册者、固定回调 ID 和原生阶段放行。HUD 维护、主菜单输入和暂停菜单绘制各有自己的放行范围。初始化、玩法、Cache、权威查询及未知回调在客机跳过。Host 队列音乐续播沿用音频回放拦截。详见 [Mod 联机接口 §7](mod-api.md#7-客机回调放行) |
| 音效 | 本地声音照常触发音频回调。应用 Host 的音乐与循环音效状态、回放 Host 的单次音效时，跳过五个音频回调 |
| 退出 | 进程退出时的保存与计数器补丁（`client_shutdown_*`）阻止客机把联机状态写进本机存档 |

隔离事件按类别计数（`game/client/isolation/client_isolation.*`），用于诊断哪类原生入口被拒绝或跳过。

## 9. 本机显示设置

- `cs display_outline <颜色序号>`：本端角色描边颜色，0 为关闭。
- `cs display_opacity <值>`：其他玩家角色的透明度。
- HUD 显示 RTT 与丢包率，数据来自连接线程发布的链路质量。

这些设置只影响本机显示，不进入协商或线格式。

## 10. 恢复与退出

- 需要完整基线时（第 5.4 节或[同步](synchronization.md)第 7.2 节的原因），连接线程发 Resync，继续显示当前画面，直到新基线装好。
- 换层准备、退休或失败时场景不再显示，本地暂停菜单随之关闭。Mod 场景在同一 run 与楼层内跨房保留；换层、换局、退出时先派发场景结束及 `reset`，再释放 Lua 已安装引用和原生查询镜像。
- 离开会话时先封输入和发布，再由 Manager 真实退休场景：音频和显示先退出，再拆卸原生字段附件，回收成员，最后把本机菜单交还原生代码。

## 11. 扩展

- **新增同步字段的客机写入**：纯值字段由生成的写入表自动处理。需要具名原生写入的字段，在 `game/client/scene/client_atomic_bindings.cpp` 中为该字段选定原生 ABI（容器、资源、字符串等），原生访问写在对应的 `*_native.cpp`。
- **新增需要放行的原生显示子调用**：在 `hooks.json` 的 `client` 组登记 Hook，在 `ClientEntry` 中增加入口，在显示推进根的 `ClientDispatchScope` 中声明它为允许的嵌套调用。
- **新增客机本地显示功能**：只改显示、不影响同步的功能放在 `game/client/presentation/` 或 `game/common/display_settings.*`，不要写进 Host 同步的字段。
