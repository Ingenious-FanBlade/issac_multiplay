## 最小读取边界与初始化说明

`0x6E02F0`、`0x60DE70`、`0x5CDB20` 分别位于 Pickup、Familiar、Effect vtable `0xB67F24`、`0xB6491C`、`0xB63BDC` 的 `+4` Init 槽，不是 C++ 构造函数。主智能体已按当前虚表更正初稿及导出脚本的错误注释，原始 JSON 保留。它们在逻辑使用时可重新初始化字段；这与池对象仅构造一次、同址复用的区别有关，仍不能从某个 State/timer 归零推出新对象身份。

本轮只推荐登记表中具有明确当前类绑定和地址闭合的 raw 字段。只对已完成 Init 且已发布到 tx-01-66 所选当前容器视图的对象按字段表逐项采样；不读取构造中的临时对象，不用字段归零猜生命周期或对象重生。不同类各用自己的候选行，不将 `State`、`Timeout`、`Cooldown` 或 `Delay` 抽象成全体 Entity 共用字段。对 unknown/not-registered 项保留状态。

采样阶段沿用 [tx-01-66 统一边界](tx-01-66-readonly-sampling.md)：同一主线程同一外层更新 token，确认标准分支 `0x955231 → 0x6FADC0`；该次调用进入普通 Room `0x6FBA4D → 0x802980` 并由 `0x6FBA52` 正常返回；标准尾部 `0x6FBBA5 → 0x8607A0` 正常返回到 `0x6FBBAA`。在 `g_update()` 正常返回后、现有 `coop::TopExit` 前且本轮 render 前复制。odd `0x6FD3F0` 只有 Player 更新，不输出全世界样本；loading/换房/teardown 或 root/Room 批前批后变化时跳过并重新读取。这里的字段稿没有重新证明 tx-66 阶段控制流。

构造/Init 行只给出少量实际观察到的起始写入。例如 NPC、Familiar、Effect、Pickup 的已登记字段在其所选函数中有直接初始化锚点；Player cooldown 在 Player Init 的伪代码/写入中为 0；Grid State 在主智能体补充的基类构造中写 0，所选 Grid Init 本体未直接写该成员；其派生虚初始化仍可改写。除此以外的 writer、构造分支、外部 reset、回调改写均没有穷尽。`Timeout=-1`、`State=0`、`ProjectileDelay=-1` 等初值本身不证明暂停、无限期、待机、生命周期或重生语义。
