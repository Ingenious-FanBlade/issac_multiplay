## 修改前失败方式

- serde_json::to_writer 直接持有 File，每个字段/标点造成小块文件写入；历史第一轮约 0.6 MB/s，不能通过截断数据或缩小 profile 掩盖性能。
- BufWriter drop 的 flush 错误可能被忽略；必须显式 flush 成功后才发布 REENCODED，写失败不能产成功报告。
- 缓冲不能无限增长或把全文件放入内存；保留每条 128 MiB 上限，固定 1 MiB I/O 缓冲。
- 必须继续解析、校验和 canonicalize 每条记录，不能直接复制输入并声称重编码；重复输出须逐字节相同，且与独立 canonical 值相同。
- 小块写入优化不得改变 JSONL 换行、字段顺序、未知引用 target 省略、宽整数、原始位串或非法记录拒绝语义。
- 单次速度不能只与历史估计比较；同一统一验收内，以旧二进制处理同一实际输入的有界前缀作为实测基线，再与新全量输出对应前缀精确比较。旧基线只取首批完整记录至约 4 MiB，避免再耗数小时；新 replay 两次处理整份文件。
- 性能和正确性一并判定，保存每次 CLI 参数/退出码/耗时/字节数、逐记录比较和直接源文件内容对照，不使用哈希。
- W01.isolation 必须从当前机器清单、人工清单与活动入口的排除列表消失，不能改成 PASS 或保留 NOT_COVERED 来凑总数。历史复制带出处，当前其余 PASS 沿用 tx-01-87。
