## 2. 操作6：缺失输入、超时与恢复

### 2.1 行为范围

1. 缺输入按**本Authority tick没有可用的同代目标命令**判定；收到未来命令不等于当前tick已有输入。另行区分“源没有新到达”和“有效输入缺失”。
2. 当前已采纳 `max_input_age_ticks=0`：连续量、held立即中性，不沿用旧移动/射击/道具按住状态。保留历史last_state用于诊断，不用它自动维持旧输入。
3. edge没有新命令就不执行；重复、过期、重绑前旧代或恢复时迟到的edge不补执行。Read重复查询不增加处理次数。
4. A/B使用相同规则；B失联、静默、无绑定或已退休，不成为A/tick等待条件。中性指输入值，不要求B的物理位置、惯性或碰撞结果不变。
5. 暂停/loading/菜单/绑定不明继续沿用已有阻断规则；暂停或渲染帧不能用于增加Authority输入年龄。room、死亡/复活、重绑清除旧代可用性；menu/run teardown不能被新输入复活。
6. 恢复只接受新鲜、合法、同代输入，按正常lead入队；重新唯一绑定时沿用已采纳的启动例外，不重放旧队列/edge，不把旧样本重新标为新代。

### 2.2 超时口径与必要实现

- 区分输入有效期与client静默超时。`max_input_age_ticks=0`不表示收到一个空tick就自动踢出B；本阶段超时至少记录静默/恢复事实并保持中性，不据此自动结束A/session。
- 明确超时诊断的阈值来源、Authority tick计时起点、跨generation规则和终态处理，写入该次实验清单。没有定义并记录阈值，就不能声称已覆盖client timeout。
- 当前last_received包含可归属的重复/非法/旧代尝试，不能直接当作有效新输入的保活依据。需要时增加专用的有效新输入到达进度，重复/非法/旧代输入不刷新它。
- 在Participant/进度与Native日志中明确记录：当前是否缺失、连续量来源tick/年龄、采取的neutral原因、静默/超时/恢复转换以及实际processed来源。采用有界记录，避免每次查询新增事件。
- 不在本操作擅自增加自动断网、踢B、AI接管或新超时产品策略；真实连接活性属于后续网络能力。

## 5. 操作9：真实Authority的B输入停发实验

### 5.1 场景与时标

真实Authority中A/B处于已绑定、正常Active状态；使用受支持且记录的配置，在同一统一E2E安排中覆盖B停止新输入 **1、5、30、120个Authority tick**，每段都有稳定输入的前置区间与恢复观察区间。段落不是四次独立测试许可。

当前B是脚本源，可在生产源发布处控制停发来验证scheduler。保持B绑定/session，不通过退休B、删除世界对象、退出run或改世界字段替代输入静默。真实网络收包/断线、传输故障与wire ACK属于后续协议/网络阶段；脚本停发不能标记网络测试PASS。

- N以已提交的Authority tick计算停发窗口，不以sleep、墙钟、渲染帧或顶层loop计数。
- 分别记录源停发区间与B effective输入缺口。停止新提交时队列内已接受的未来输入可以自然消费，不能立即断言B已中性；恢复的lead也可能带来后续空档。
- 保存停发前队列中的目标tick与恢复新命令的target；不清空队列、补造序号或重绑来“对齐”实验。如果要求恰好N个effective缺失tick，脚本须显式安排target并记录依据，不能混用两种N的口径。
- 恢复使用新的合法sequence/target，按正常lead入队；持续绑定下不滥用startup例外，不追补静默期间的edge。

### 5.2 每段要实际观察什么

1. Authority tick仍跟随已确认的正常原生模拟；记录标准Room/odd kind、正常返回、post-state状态、commit与回执，不能只看墙钟变化。
2. A继续发送正常输入，并有真实游戏中可观察的安全动作，例如空旷区域往返移动；仅query非零或driver计数不算世界动作证据。选择与持久副作用授权相容的场景。
3. B在可用的已排队命令消费完后按操作6中性，不重复旧边沿；恢复后仅新命令生效。伤害、惯性或碰撞导致的B移动不与输入中性混淆。
4. 停发/恢复不新增all-client ready等待，也不绕过共同AcceptInput；实际收到、接受、Resolve、processed和source/generation均能关联。
5. 读取或publication出现缺口/失败时，记录事实、实际tick与停用原因；不能为了PASS忽略事件丢失或把采样gap写成完整世界。
6. 结束时关闭输入/publication、处理在途callback和pending世界批次，按既有事务恢复目标字节与对象退休，记录恢复状态；自有对象/DLL继续遵守常驻NEVER回收，不强制卸载或盲目重注入。
