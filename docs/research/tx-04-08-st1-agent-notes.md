## 需保留的核对边界

- Parent 主审原始 vtable 抽查显示 Entity slot 0 指 `0x6A3EC0` 删除包装，Entity slot 1/10/17 指 Init/Remove/ClearReferences；Player、NPC、Pickup 对其中部分槽有不同覆盖目标。因此表中直接地址不证明整个继承闭包都经过同一地址，派生覆盖完整盘点留 ST5/ST6。
- GridFactory 的完整 ZHL pattern 是 `558bec6aff68????????64a1????????5051535657a1????????33c5508d45??64a3????????8bda`，完整扫描只命中 `0x706100`。早先一次误报 `0x7045E0` 是误用截短 pattern（少了 `51`）的假阳性；它不是完整 SDK 签名的碰撞，已纠正，不作为入口证据。
- `UNKNOWN`：Publish 的 raw EAX 类型/语义、Replace 的官方 `.zhl` 缺失、GridFactory 当前 hook 实际注册定义、各类派生虚表完整覆盖与活动 REPENTOGON hook 链、Morph/Restore/Spawn 全部嵌套完成判定、Door/GridFree 实际释放与复用结果。后续问题分别属于实现接入或 ST2–ST8，不在此静态入口表中冒充完成。
- 主审静态复核后修订：GridSpawn 的 idx 与 VarData 是 `i32`，type/variant/seed 是 `u32`，bool 返回只认 AL；PlayerCreate 存在 max-player 返回 null 分支；入口字节是观测窗口，可能截在指令中间，Factory 的 force 读取点位于函数体 `0x6EC5C5`。此注记保留本轮主审发现的更正。
- 本次只读 IDA 与静态源码；未改 IDB、游戏文件或其他工程文件，未执行测试、构建、游戏、哈希校验，也未设置 gate。ST1 的表格交付不表示 ST2–ST8 或任何运行时结论完成。
