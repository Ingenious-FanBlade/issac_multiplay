## 1. 实现前的失败模型

| 类别 | 必须能识别的失败 |
| --- | --- |
| 来源 | 录制关掉就无状态；三 Peer 重复扫描；全域 Lua／DOM 每帧阻塞；普通／odd 混拼；未实际更新身体伪造 60 Hz；低频 Context 已失效仍复用 |
| 身份 | 菜单等待 Scope 当真实 run；旧 Intent 借新路由发送；body／participant 混同；池槽／shape 复用；删一条关系误删身体；同 sequence 不同 payload 被接受 |
| 传输 | 64 KiB 上限误伤 Baseline；未协商大分配；分片头无法区分 lane；缺尾片永远不补；重复 ACK 续命；控制缺号死锁；取消后旧片复活 |
| 确认 | 收包／解码就 ACK；Player 子范围 ACK 冒充整房提交；ACK 丢失重做构造；未知／未发送版本 ACK 被 Host 采纳；单域成功掩盖其他域失败 |
| 连续变化 | 快照合并漏最终删除／归零；新资源未到先写；旧普通帧覆盖较新 PlayerPost；不断取消旧目标导致应用饥饿；一次变更后静止永不收敛 |
| 带宽／时序 | 10 Mbps 被按每端计算；忽略控制／IP 头／重传；30 Hz 和 60 Hz 重复使用同一份预算；roster 降频使输入 20 Hz；用重复包充发布帧数 |
| 原生应用 | 每帧重建资源／场景；跨线程对象访问；写到一半仍显示或 ACK；错误线程／context／Lua state 后继续写；失败退休放掉在途资源 |
| 隔离／退出 | Client 运行第二份碰撞／AI／随机／拾取；输入代次复活；Host 等慢端；网络停止但访客世界仍存活；保存／成就／统计写入；关闭中悬空 callback |
| 验收方法 | 只比 DTO 自身；对比不同 tick 的最新帧；Rust 模拟器顶替真实 Client；离线导入顶替网络；缩小负载或删失败项；仅文件末态无变化就称全程隔离 |

这些失败方式用于实现和统一 E2E 的错误注入，不授权在分析／实现期运行实验。未知 ABI 或 owner 先按研究计划解决，不能靠崩溃试验猜写。

### 2.1 实际拓扑

- P2 为 **两个同时运行的真实 `isaac-ng.exe`**：Host＋C1；P4 才扩为 **四个同时运行的真实实例**：Host＋C1／C2／C3。各有真实安装、资源和独立用户数据路径，两个阶段都至少跨两台实际设备；VM 可参与其他 Client，但应记录物理机／VM 分布、CPU／内存／焦点与网络拓扑，不能把同机窗口称为跨设备。
- 所有 Client 在开局前连接并分配冻结身份；Host 是唯一权威。Rust 只编排、限速／损伤和只读归约；不得代替真实 Client 或把世界文件放进 Client 来完成网络场景。
- 优先局域网可达地址，采用同一总上行限速器覆盖 Host 到当前阶段全部 Client 的数据报（P2一个、P4三个）；可用用户态 UDP 代理，无需修改系统全局网络策略。代理转发真实协议，来源仍是 Host。包数双计会明确排除代理内环。
- 逐节点记录实际协议／声明版本、资源配置和进程身份，不计算任何哈希。缺少必要设备、人工准备或操作授权时只说明该部分未执行，不换成顺序离线样本判通过。

## 3. 网络档与定量判定

所有档的 Host 总上行上限均为 **10 Mbps**，模组自身按 7.5 Mbps 持续预算。P2 的唯一 Peer 额外按四人公平份额 **312,500 byte/s** 及相同 lane 预算限速，不借用不存在的其他 Peer 份额；P4 再验证三端总和。Client 输入／ACK 上行另行记录，每端初始保护预算 50 KB/s；其流量不偷算进 Host 上行，也不能不计反向瓶颈。

| 档位 | 延迟／损伤 | 验证内容 |
| --- | --- | --- |
| N0 | 无人为丢包／重复／乱序，实测 RTT ≤40 ms；不满足则明确环境不符，不伪称 N0 | L1／L2 的频率、字节、持续互动和正常控制 |
| N1 | 人为增加往返 80 ms（双向各 40 ms），每方向抖动 ±10 ms；实际 RTT 同时记录；0.5% 随机丢包、1% 重复、2% 包延迟额外 50 ms 形成乱序 | L2 至少 120 s，传输收敛、完整范围恢复，不要求每次发送都抵达 |
| N2 | 在一个 Client 的 Baseline 明确丢首片／中间片／尾片及部分 ReceiveAck，分别重发；保留其他两端正常流量 | 选择性补片、进度超时、ACK 幂等和其他端频率 |
| N3 | 一个 Peer 下行停止 2 s（心跳上行可保持），再恢复；另做其 0.5 Mbps 持续 30 s；不越过连接关闭条件伪称重连 | 同连接完整 Baseline 恢复或明确独立停止、其余端不停 |

P2 完整执行 N0—N3：N0／N1 用 L0a／L0b，N2 对唯一 Client 完整执行每种分片／ACK 损伤，N3 完整验证 Host 推进、慢端处理和恢复。P4 再对三端执行同一套损伤，加测其他健康 Client 的持续流量／应用与总预算竞争。N1／N2 的故障由同一入口内部可复现的注入序列确定，记录实际命中的包／范围；不以“设了概率”代替实际观察。更长断网、重新连接、Delta 缺基线链和多基线淘汰矩阵仍归 22／30，不是本tx两人阶段遗漏项。

### 3.1 必须满足并分别报告的指标

1. **频率**：N0 合格稳定段 WorldDynamic 发布与原生应用均值 ≥29 Hz，普通来源约 30 Hz；PlayerFast 调度机会约 60 Hz，实际具备约 60 Hz 来源的身体发布／应用均值 ≥58 Hz。对只实际更新约 30 Hz 的身体，须达到其合格来源的 **≥97%**，并列出真实 Hz 和缺席原因；不能由此宣布全八身体 60 Hz。来源未接线不算“原生缺席”的合法豁免。
2. **间隔和覆盖**：N0 合格稳定段普通／身体动态提交无超过 **100 ms** 的非声明缺口；统计 1 s 窗口分布、p95／p99 间隔及 source→publish→receive→apply 计数。不能排除网络丢包、预算反压、解析慢造成的失败来提高频率。暂停／结构事务单列时长和原因，稳定段定义在执行前确定。
3. **带宽**：所有实际包按合同计费；每 Peer 和三端总量、各 lane 及重传归约一致。任意窗口符合 `937500 × 秒 + 24 KiB` 总桶上界和每 Peer 借用规则；持续供给速率 ≤7.5 Mbps，burst 单列。10 s 窗口按同一公式的上界约为7.520 Mbps，100 ms 短窗也按公式判定，不把允许的有限突发误记为持续超速。P2另受312500 byte/s＋8 KiB的单Peer上界。
4. **首次准备**：L1／L2 压缩 Baseline 及冷端缺失的全部必需上下文／结构／资源消息合计 ≤1 MiB，从 Host 发起准备到 Client 真实画面就绪 ≤10 s；三端同时准备分别计时。不能只计 manifest 或假设网络缓存已存在。记录采集、编码、压缩、排队、传输、解码、原生构建各段，不用网络理想值代替总时长。
5. **状态年龄**：N0 动态已应用状态相对真实 Authority 进度的年龄 p95 ≤200 ms，最大 ≤500 ms；N1 p95 ≤350 ms，最大 ≤1 s，超过 500 ms 已有明确陈旧状态。年龄用 Authority tick／服务器回显估算并标误差，不直接相减异机单调钟。
6. **最终收敛**：N0 单次变化后静止，最终数值／显式空／删除在 ≤500 ms 内确认；N1 在 ≤2 s 内确认或进入有原因的完整恢复。恢复成功后最新最终态必须一致，不能仅证明“发过 resync”。
7. **CPU 与内存**：稳定动态 Host 新增主线程采集／发布、Client 动态安装各 p95 ≤2 ms／p99 ≤4 ms；其他阶段分列。复制自有各池符合合同，重复准备／更新／退休后无无界增长；原生资源和全进程内存独立报告，不能拿工作集代替 owned bytes。
8. **输入**：四组均有真实物理非中性输入上行、Authority canonical 接纳／处理以及对应实际原生 consumer 见证；按普通／odd 和每身体分别报告。N0 正常新命令被过期拒绝比例目标 <1%，目标 tick 偏差分布必须列出；边沿每个新有效动作 exactly-once，重复／暂停／旧代次不得重放。调整输入有效期或复制旧 held 不得用于通过。

以上同一频率、时延、CPU 和单 Peer 预算指标先适用于 P2 的 L0，再适用于 P4 的 L1／L2；首次准备 P2 计一个冷 Client、P4 分别计三个；输入先查两组再查四组。总量上限按相应实际 Peer 数与固定每 Peer 份额计算。两人达标不代替三端竞争下的四人达标。

这些是 21 的目标，不是当前已达到的事实。若采样、带宽或 CPU 使目标未达，应在同次 E2E 修复并续验；无法完成则如实说明具体缺口，不能只用“画面能动”宣布本计划全部通过。

## 5. 状态、画面与故障的证据方法

E2E 在 Host 采样时保留有界、短期的指定版本规范值，在 Client **实际提交当刻**取得 native inspect 的纯值；以 session／route／scope／world/body sequence／key／shape 对齐后逐字段比较，不计算状态哈希。浮点若协议未量化则保留原表示；已有明确计算／绘制差异按具名字段语义说明，不能用全局大容差掩盖错误。

画面检查关联实际提交版本和 render 时刻。需要静止视觉对照时由 Host 控制一个有定义的输入中性／稳定窗口，当前阶段全部实例保持网络运行；不能为了截图冻结目标序号后又把该段计作 30／60 Hz。基础战斗、拾取、双身体、资源变更及一次恢复后画面均需在两人全套中实际观察，四人阶段再按扩展人数验证。

网络损伤注入走真实报文；格式错误可从实际包做限定变更，但有效世界样本必须来自正式 Host 来源。故障注入仅 E2E 编译，限具名边界，不暴露任意地址／函数 RPC。首个失败、后续恢复和最终通过分别记录，不抹去失败历史。

## 6. 统一执行顺序与连续修复

I39 从同一入口完成产品／E2E 构建和部署。**先 P2 全套**：E01—E26及其全部子用例、L0a／L0b稳定段、L0c结构变化、N0—N3、全部负向／故障／隔离／退出、受影响回归和产品路径，连续修复续测到全套通过，并完成两人结果归约和正常收口。**再 P4 全套扩展**：将已跑通的整套测试扩到L1—L4和三个Client重跑，增加三端竞争／公平／隔离与四组八体断言。不能先在两人做少量验证，就转到四人首次调试剩余E项。每次启动仍单独提醒并取得所需准备确认；属于同一tx，不默认在两人全套通过后等待新实施指令，但四人所需人工准备仍须具备。

每个E编号及子用例分别登记P2／P4的NOT_RUN／RUNNING／实际失败／修复后通过；P2全套清单不设以人数为理由的SKIP／N/A，场景准备失败仍未完成。修复后继续失败项、受影响项和未完成项；公共codec／Scope／来源／资源变更必须覆盖受影响续验。P4发现会破坏P2结果的共用缺陷时，先修复并补验受影响两人项，再继续四人未完成项；无关P2成功不机械重跑。不能以20离线通过代替本次两人网络全套，也不能以某项四人通过补齐此前没有执行的两人项。

只在用户停止、缺少必要配合／授权或确有无法自行解决的问题时中断，保留继续所需的最少进度、错误和环境恢复信息。正常结束清理临时包／截图／日志／采样和代理状态，恢复本次实际变更的配置；删除前核对绝对路径位于本次临时目录。功能设计、schema、目录和正式发布内容照常保留，不要求最终 artifact 包。
