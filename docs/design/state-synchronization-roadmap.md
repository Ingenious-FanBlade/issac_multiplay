## 1. 最终产品与完成定义

完成意味着普通用户在目标环境安装模组后，能使用真实游戏客户端建立联机、选择角色、从开局持续游玩到正常结局或 Game Over，能够切房回访、换层、走特殊路线、使用原版角色／物品／武器并正常退出和 Continue。最多四名参与者，一名房主加三个游戏客户端；双子等一个人多个 EntityPlayer 的角色保留原生控制与资源语义。

| 方面 | 流程完成时必须得到的行为 |

## 2. 从观测到可玩产品的职责闭合

每个功能都要落实以下链路，而非只有字段名或某个网络消息：

```text
公开语义／必要补充研究
  → Authority实际采集与稳定身份
  → 复制模型／状态或事件的归属
  → 编码、传输、版本及恢复
  → 客户端资源和原生对象安全应用
  → 实际可见／可操作结果
  → 生命周期、失败处理与整体验收
```

完整观测目录是输入，不自动等于网络 schema；字段逐项选择“复制状态／表现事件／房主独占／客户端本地”，写出理由及对应行为。房主独占 RNG／AI 内部状态不意味着观测阶段可以省略它，也不意味着展示客户端要恢复成第二个模拟器。

09—14 的观测实现使用[按域拆分详细设计](observation-expansion/domain-observation-architecture.md)：10 迁移 Entity／旧 Grid 并交付公共接口，11—14 接入其余域。观测域、native／Lua 来源和消费端分别组织；采集 epoch、scope、域覆盖和引用结果保留原语义，录制不是正式状态消费的运行前置。15 及以后从实际自有值记录选择复制模型，不直接将旧 RawBatch 或新观测 envelope 当作 wire，也不将不同回调数据拼成原子快照。本次同步仅修订设计入口，未启动实现或测试。

优先两套本地 Wiki 与公开 Lua；只对创建／应用副作用、公开接口不足或具体版本疑问补源码与必要 native 研究。能读取不等于能安全写回；即使调用 Lua setter，也必须理解其实际作用。研究与实现并入对应实质 tx，不连续拆成仅研究而没有功能产出的无限任务。

## 5. tx-04-23—29：覆盖一整局游戏的全部语义

### tx-04-23：切房、普通传送与回访事务
