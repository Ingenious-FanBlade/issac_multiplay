## 实现前确定的失败模型

- 连接只允许从没有本地 run、没有排队 Start／Restore、没有 Host／Solo／录制的稳定菜单进入；已有 Continue 由访客原生档拥有，不能载入、删除或覆盖来借作客户端世界。
- 能力／目标版本／资源／Mod 声明矛盾、nonce 重复、名单已满、非法长度／分片／消息／身份或旧 connection 必须拒绝。未完成协商不能 Join 或应用输入；端口只属于本项目独立会话。
- 网络线程只处理有界自有值；唯一 main owner 执行连接／停止、采样和回执消费。客户端不建立 Authority 时钟，整个 Manager 原链短路，菜单／加载／失败／退休均保持相同边界。
- 物理源按显式 device key 唯一选择；断开、焦点丢失、UI 屏蔽、generation 变化和等待均清除旧边沿。使用统一 canonical 和相反射击后按优先语义，发送失败不能消费边沿，重复命令不能重复触发。
- 输入回执与名单／服务器 tick 分开，零输入进度不能伪造 InputAck。收到世界 DTO 不等于原生应用；本tx只等待世界，不进行 seed 重演。
- 失联、协议失败、停止和进程退出先关输入／publication，网络线程退出后才交还 Off；不调用 Game::Exit(false)。Host 其他参与者继续模拟，退休 ordinal 不挪给另一人。
- 验收只在完整实现后开始；不新增单元测试。仅覆盖新增客户端链和受影响的 Host 接入／角色生命周期，不重复09—15已通过且不受影响的观测／codec矩阵。按文档跨设备一 Host＋三真实游戏 Client；Rust 只编排，不能代替 Client。

## 接线与运行

`mod/src/net/live.*`使用15的ICSR v1与ICRF分片、严格能力/目标版本/资源/Mod声明；控制面收紧到64KiB、4096节点、24层、64片、两个重组候选。Host共用原UDP监听socket，按来源和冻结ordinal独立保存ICSR或历史ICSN端点；游戏客户端使用ICSR，不依赖Rust。随机nonce与独立connection确认完成后，主线程才AddParticipant/Join。输入映射为原ReceivedInput，经既有generation/窗口检查和Participant去重、Resolve及原生consumer；没有第二条写Player旁路。

主线程Client控制块与Authority SessionRuntime分开。Manager外层常驻wrapper在消费Start/Restore之前运行独立Client消息泵，Connecting/AwaitingWorld/Failed/Retiring全部不进入原生Manager链。只从稳定菜单连接，拒绝已有本地run、排队Start、Host/Solo和录制冲突。等待界面使用纯UI mod的菜单绘制与原生已有字体；菜单原render继续交换缓冲，没有创建Room/Player/Camera或自有Sprite。完整世界/任意gameplay Mod隔离仍归17，本tx不声称世界壳已准备或world_complete。

输入后端只在独立受控Input owner更新；物理设备按明确key唯一选择，不借本地Player身份。后端锁、poll exactly-once、设备消失、焦点/UI屏蔽及代次检查仍保留。Host/Client共用CanonicalizeShooting和canonical V2，边沿用16项FIFO，不合并重复按键；每个新服务器tick最多产生一个新sequence，连续量与边沿走相同正式上行，最多四份原值命令冗余。穿透实测发现直接对滞后的roster tick加2会令所有上行过期，现用同机时间区间回显测往返传输耗时、服务器实际tick/单调时间差测速率，投影预计抵达tick后仍加原lead=2；主线程快照到网络发送的驻留时间及Client主线程取包延迟也计入。单调时间不创建或推进Client/Authority模拟时钟，不修改Host的过期拒绝、去重、64tick未来窗口或max_input_age_ticks=0。丢包/高延迟的完整体验与性能仍由22/32完善，不保证穿透降低延迟。

Host的`roster`控制消息发布四参与者位图、server tick、绑定generation和input_enabled；暂停/加载/未知绑定时Client清除边沿。非零实际处理进度另发InputAck，绝不发送AppliedAck。Client网络线程只持有纯值队列，主线程不等待网络；正常停止关输入后轮询线程完成，下一轮才交还Off。原生main关闭判断先请求Client退休，不通过Game::Exit(false)取消连接。退出后的访客持久全链隔离仍须由17/31完善，不能以本tx没有本地run外推已完成全部持久闭包。

## 安装、命令与SakuraFrp入口

每端需要相同目标游戏及官方REPENTOGON 1.1.3，加载`zhlIsaacCS.dll`并启用配置；必须启用配套纯界面`ui/isaac-cs-ui`，提供Host/Join/Stop和等待提示；无UI近期菜单心跳时Client入口明确拒绝。16本身不需要世界观测Lua、测试玩法夹具或Rust输入客户端。首次连接仍要求没有第三方gameplay Mod；版本/资源声明不是安装内容摘要验证。

- `cs host 27090`：Host监听配置地址，产品默认`0.0.0.0`，一个UDP端口服务三个Client。
- `cs client <IPv4> <UDP端口> [本地设备key=0]`：从稳定菜单连接；当前只接收数值IPv4。服务器自动分配1—3，不把身体数当参与者数。
- `cs stop`：当前Client安全退休，或停止原Host；切换角色先Stop，再等`role=Off`。
- `cs status`：role/client_state、参与者/位图、wire session/connection、generation、采样/上行/处理ACK及错误。`client_world_applied=0`保持真实边界。

本次用户指定SakuraFrp：配置**UDP**本地目标`127.0.0.1:27090`，Client填它公开入口的IPv4和映射UDP端口。无需转发本机TCP控制口27091；三个Client共用同一个入口。模组只负责监听该端口，隧道创建/账号/节点和远端桌面由实际环境提供，不根据软件名称推定已连通或已测试。

## 统一E2E入口与续作

`scripts/accept-tx-04-16.ps1`的Build只构建。Run按NodeRole执行真实游戏；每次启动会提示停止手动键鼠，沿用已开启SkipIntro的自动启动，不重复请求测试授权。

- `-Stage Run -NodeRole Local`：本地真实游戏覆盖连接等待、键盘poll、原生模拟未进入、超时、连接中停止、重新连接和Client→Host→Off。UDP黑洞只用于超时，不作为Host替身；该组不代表网络四端通过。
- `-Stage Run -NodeRole Host -Cohort <本轮名>`：房主原生新局，等待三个真实游戏端，四参与者/至少五身体、逐ordinal实际native consumer和处理进度，然后统一断开并正常退菜单退出。

- `-Stage Combine -Cohort <同轮名> -NodeDirectories <四个结果目录>`核对一Host、三Client、四个不同设备名、同wire session、冻结ordinal1/2/3和全部节点通过。不能把四个本机进程结果升级为跨设备通过。
