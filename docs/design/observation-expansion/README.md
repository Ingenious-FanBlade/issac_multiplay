## 3. 完整观测的含义

完整观测包括**目录完整、状态采集、变化过程与生命周期**。对象枚举、类名识别、API 存在、单次字段有值分别只是其中一部分。

1. 目录以两套本地 Wiki 中的类、继承成员、扩展成员、关联容器、枚举和回调为起点，覆盖全部相关公开观测语义，不只摘取本文示例。
2. 每个成员明确归入只读状态、派生查询、真实发生时的操作／事件、配置资源，或具体缺口。动作接口归入目录不表示为了采集而调用该动作；同义／继承成员可映射同一个规范字段并保留来源。
3. 对每个应采集项记录适用类别／变体／角色、版本、参数域、默认参数、单位、有效时机、返回值与缺失语义。查询参数可能改变含义，不能只记录一个默认调用就称为全部语义。
4. 观测范围包含模拟相关状态与展示相关状态；各实例、变体和角色出现时必须进入其对应合同。特殊接口如 EntityDelirium、Slot 不因不在旧七类中被排除。只有公共头部的未知类仍是缺口。
5. 没有公开接口的需求继续列明，按第 4 节补充，不能因 Wiki 未暴露而静默删去。也不承诺通过公开 API 得到引擎所有私有内存、任意 Mod 闭包或可继续模拟的完整存档。
6. `nil`／不存在、空集合、零、当前不适用、接口不可用、未捕获、失败和截断分别记录；未知不补零。缺口和未执行场景如实保留；目录完成不替代运行覆盖完成，也不把保留 UNKNOWN 当作已完成该项观测。

因此，每个 tx 的交付须分别陈述“目录中已解释的范围”“实际实现的采集范围”“本次 E2E 观察到的范围”和“尚未完成的缺口”。不能用统计总字段数冒充任意场景的完整性。

## 4. Wiki／公开 Lua 优先的实现路线

资料根目录：

- 原版：`F:/projects_isaac/IsaacDocs/docs`。
- REPENTOGON：`F:/projects_isaac/REPENTOGON-1.1.3/docs/docs`。
- 目标游戏：官方 REPENTOGON 1.1.3 与 `Repentance+ v1.9.7.12.J273`；Wiki 内的其他版本标签不能直接外推到目标环境。

按以下顺序选取来源：

1. **先查 Wiki，优先直接使用公开 Lua 状态、Getter、容器和回调**。文档语义清楚且适用时，不要求逐项寻找 native 偏移、IDA 对照或双实现比对。
2. 只有版本可用性、getter 副作用、对象有效期或事件时机等有具体疑问时，查相应官方 SDK／公开绑定源码。不是对所有 Lua 接口的强制第二轮审查。
3. 对公开接口确实不能满足的具体字段／事件，再做必要 native 研究，或复用目标版本已解释的只读点位；记录缺什么、为何公开接口不足、补充范围是什么。

Lua 采集可以成为正式观测来源，而非只能当测试夹具。其注册、主线程调用、启停、schema 发布与生命周期需要作为自有观测模块设计；与现有纯界面 Lua mod、测试夹具分开。观测回调不得替换玩法裁决或修改被观测值。网络／写盘线程只接收已经复制的自有数据，不持有游戏 userdata 或借用对象。

函数名不能证明只读。例如 ItemPool 的某些 `Get...` 会进行抽取或使用默认 `Random()`；`RandomCoinJamAnim()` 产生随机选择；`EntitySaveStateManager:GetEntityData()` 可创建数据表。应使用已有状态／不会创建内容的查询，或记录真实调用的输入和原始结果；不为采集再次执行。`pcall` 只处理 Lua 错误，不能撤销已发生的副作用。

## 5. 跨 tx 共用的记录合同

本节的数据含义落实到[按域拆分详细设计第 4—7 节](domain-observation-architecture.md#4-公共数据合同)的 context、DomainResult、SubjectKey、引用及 scope 合同。域是数据归属，native／Lua 是来源，录制／后续正式状态消费是消费端，三者分别管理。公共调用职责见该设计第 5 节；未来新增域按第 12 节交付，不把所有字段塞入旧 RawObject 或扩大一个总采集／编码分支。

记录先用于本地观测、离线重放和分析，不预设未来网络 ABI。推荐明确分为目录、状态样本、事件、关系与缺口：

| 记录内容 | 必须说明 |
| --- | --- |
| 来源与字段目录 | 稳定字段 ID、类型、语义、Wiki 路径／成员、来源方式、适用版本／对象、参数域、所属 tx、采集实现状态 |
| 采样上下文 | session／run／floor／dimension／room 标识与代次，Authority tick（若有）、实际采样阶段／序号、来源有效期 |
| 对象身份 | Entity 与 Grid 分域；Player 身体复用其 Entity 身份，不另分配互不关联的第二个对象 ID；participant 与 control group 另列；地址／索引只作本地诊断，不作跨时间唯一 ID |
| 值与引用 | 自有不可变数据、原始值与规范值的对应、集合 membership、存在性、NULL／未解析／冲突等引用语义 |
| 生命周期与事件 | 真实创建／移除／替换／切换的观察窗口，FIRST_OBSERVED 与已观察出生分开；事件 ID、阶段及关联对象 |
| 有效性 | 可用／不适用／未知／失败／截断的具体原因，样本覆盖范围和 budget，不能静默丢字段或对象 |
| 来源关系 | 多个观察点对应同一事实时的关联、差异与各自时间，不把不同回调时刻的数据拼成虚假原子快照 |

同一对象的字段由一个规范模型管理；后续 tx 扩展或建立引用，避免重复字段产生互相矛盾的真值。采样频率按生命周期／变化频率区分，不要求所有配置、楼层和 HUD 状态每 tick 全扫。

普通后态、生命周期／过渡、render 和实际调用事件有各自 scope，tick 可以为空；同一窗口先登记主体，再采集字段和解析引用。缓存保留实际来源 scope、revision 和失效依据，不能把旧值改成当前采样。域 scope 完整与声明组合完整分别计算，未启用、未实现、未采集、不适用与空集合分别表达。

正式纯值采集不依赖 world_record、trace 或文件成功；采集 epoch 与 recording generation 分开。旧 min-read-v1 按原合同保留为兼容投影，新域使用显式版本化的独立记录合同，二者来自同一次读取。具体格式和迁移安排见[详细设计第 10—11 节](domain-observation-architecture.md#10-记录格式与旧-profile-兼容)。

已有完整普通采样窗口、odd-only gap 和主线程规则继续适用。新增 Lua／render／过渡来源必须明确实际时序；无法证明同一窗口时记录为独立 scope，不能仅凭 FrameCount 相同就合并为完整世界样本。读取窗口污染或跨代变化使相关 scope 明确不完整，不阻塞 Authority 等待全员。
