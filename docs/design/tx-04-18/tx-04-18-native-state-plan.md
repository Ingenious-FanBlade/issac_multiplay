# tx-04-18：以 create／remove／change 应用原生 Room／Grid 状态

日期：2026-11-01，Asia/Singapore。状态：**原生Room／Grid应用与17配套调整已完成，统一E2E最终29/29 PASS。** 按用户要求在同一tx内连续定位、修复和续测，全部通过后提交。失败历史见第12节，最终范围与结果见第13节；第10、11节保留此前实施阶段的历史时点。

执行规范见[现行项目规范](../../refactor/project-conventions.md)，全任务关系见[路线图](../state-synchronization-roadmap.md)，既有模型／版本合同见[状态同步设计](../state-synchronization.md)与[15实现](../tx-04-15.md)。本文替代18旧方案中“自有 Room/Grid 展示节点＋原版资源捕获／绘制重放”作为正式实现路线的决定。旧实现、原始静态事实、10/10受控用例结果及原版补全失败记录保留为历史，不改判为本方案通过。

## 1. 完整目标与完成行为

Authority发送对象的存在性、身份、结构和最终状态。Client在主线程建立对应的**原生 Room／Grid 对象**，执行 create、remove、change，让游戏依据这些状态维护本地资源、Sprite、缓存、动画和原生渲染。房主仍是唯一玩法裁决者。

18必须交付活动房间的实际形状／布局／背景／环境、448格存储及八门视图、全部27种非空Grid类型与17个派生类的原生应用；包含当前状态、保存描述、同格替换、删除和必要关系。全部12种房形进入本tx。不能以独立Sprite正确出图或保存了字段值替代原生对象状态已经应用。

本地安装的原版资源由游戏正常管理。需要传输的是资源选择所依赖的状态：配置身份、类型／变体、环境、实际装饰选择、必要的动画／外观状态等；没有公开应用入口的具体项补必要native适配。**不再以捕获／传输RGBA、生成surface像素、最终quad／顶点、GL状态或重放绘制批次作为18的实现方向。** 截图可作验收观察，不能成为世界状态或客户端画面的输入。

“游戏维护外观”是实现目标，不是假定任何字段赋值都会立即刷新。各类型须明确其原生初始化／恢复／外观刷新依赖；有需要时在原生对象内应用Authority给定的Sprite姿态或资源选择，不另建一套Room/Grid绘制器。

## 2. 三种语义及其与既有协议的关系

沿用既有Delta定义，对明确基线B和目标T：

```text
create = T中存在、B中不存在的主体及其完整当前状态
remove = B中存在、T中不存在的主体
change = B与T中同一主体的字段、关系或结构的最终状态变化
T = Reconstruct(B, Delta(B,T))
```

旧设计公式中的`Update`与这里的`change`同义。三者是世界状态语义，不是要求对每次原生调用发送一个包，也不是远程函数调用。15当前使用完整component替换与显式删除编码；18复用它重建目标，不为了三个语义重做wire或提前实现22的稀疏Delta。

| 语义 | 客户端必须实现的行为 | Room／Grid中的例子 |
| --- | --- | --- |
| create | 在正确上下文建立合法原生对象，恢复完整当前状态及关系，再开放展示 | 建立活动Room载体；在指定格创建岩石、坑、门，并直接恢复成服务器当前后态 |
| remove | 解除引用、成员和别名，调用适合该对象寿命的原生移除／退休路径 | 岩石对象确实消失；门主体移除时清理Grid槽和门视图 |
| change | 保留逻辑身份，写入最终字段／关系，完成必要原生外观及缓存刷新 | 门状态改变、坑桥接、岩石破坏后态、环境色／水量变化 |

创建是“让该主体以当前状态存在”，不重演出生以来的动作。移除是“该主体不再存在”，不等同于Damage、Destroy或播放死亡。变化是最终值覆盖，例如`State=目标值`，不发送“再伤害一次／再按压一次／再开一次门”。

### 2.1 身份与存在性

- Room由session／connection／run／floor／dimension／room／scene上下文定位；Grid沿用15的`(run, space=2, id)`。原生指针只留在主线程映射中，不进入网络身份。
- 同格不是同主体。同格旧K1退休、新K2出现，语义是`remove(K1) + create(K2)`；八门视图中的同一Grid只是别名，不重复create。
- Grid仍存在但进入破坏、残骸、开关等状态，语义是change。具体存在性以完整Authority成员集及已知生命周期为准，不能按State的某个数值猜删除。
- 同一逻辑身份发生结构变化时沿用身份／shape revision合同。若原生类型不兼容，可以在客户端内部重建载体并保留逻辑key；这是change的实现细节，不能伪造服务器remove/create，也不能只改Type或vptr冒充重建。
- 删除只来自显式remove或完整目标成员集差异。Partial、gap、少一个分片或本包未提到主体，均不构成remove。

### 2.2 基线重建与幂等

客户端先从指定B重建完整T，再比较**最后成功应用的本地目标C与T**，得到本次原生create／remove／change计划。不能把相对B的create或字段patch直接执行到任意当前C。

例如B中岩石State=0，T1中变为2，T2又回到0；即使Delta(B,T2)没有该字段，本地也必须从T2恢复为0。相同K已因T1创建后，后续基于B的重复create不能再生成第二个对象。重复版本不重复执行，旧版本不覆盖新版本，同版本不同内容报告冲突。

完整Baseline可以在空载体上转成Room／Grid的create和状态恢复；已有健康载体时按C到T调和。部分原生应用失败后不再相信旧C对应当前对象；保持停显，清理已执行部分并按完整目标恢复，不盲目重试剩余操作。

## 3. Room与Grid的原生应用规则

### 3.1 create

1. 完整准备自有目标数据，确认scope、资源／配置版本、成员、引用和必要上下文可用。
2. 通过适合J273的原生创建／恢复入口建立Client所需Game／Room载体、有效容器及渲染上下文。Room通常受Game／Level持有，不能默认`new Room`后替换全局指针即可使用；具体入口是本tx必须解决的实现项。
3. 应用Authority明确给定的RoomConfig／Override、形状、布局和环境；建立资源初始化所需的最小楼层／维度上下文。不得本地再抽一间房或由同seed跑出一份独立玩法世界，也不得以普通StartGame／整层生成的副作用代替载体准备。
4. 对每个Grid使用目标类型／变体、位置、描述和必要初始化参数建立正确原生派生对象，再恢复当前State／VarData、子类状态和关系。seed可作明确的初始化参数，但不能代替最终后态。
5. 先建立内部主体映射，再解析门别名、Grid引用等关系，按类型完成必要PostInit／外观准备，最后检查实际原生对象与目标一致。

初始化可以使用引擎的资源管理和原生构造流程，但其玩法生成、奖励、实体生成、回调和随机选择须按第4节隔离。不能将Init一律禁止后再手工重建全部资源，也不能把Init存在当作允许一切副作用。

### 3.2 remove

Grid移除前先核对key、当前原生对象和槽位仍一致，解除入向引用、门别名及自有映射，然后按已理解的原生寿命移除。需要保留的装饰、path／collision后态由目标模型决定，不能让本地默认清理结果覆盖Authority结果。

同格替换必须在新建前实际释放旧槽；采用可立即完成的适当移除入口，不为等待延后移除而推进整间Room的Update。门需要单独确认全部别名及额外资源寿命，不能假定移除Grid槽必然清掉门视图。重复remove幂等，不访问已退休对象。

Room remove表示退休该Client场景载体、其Grid与相应资源并使引用失效；不表示向Authority发送退出或调用会写Continue／统计的普通结束流程。18实现单场景创建／退休，23负责其网络切房事务，24负责离房世界。

### 3.3 change

按字段的**应用含义**分组，复用11／12／15已有目录，不把观测目录中的每个Getter机械变成setter：

| 状态组 | 应用方式 |
| --- | --- |
| 当前标量／子类状态 | 使用语义明确的公开可写字段或setter；必要缺口补native入口／已核定写入，写最终值 |
| 描述与运行状态 | 恢复描述和当前字段的真实关系；Desc／GetSaveState别名不能当成两个独立对象重复写，不假定描述包含全部运行状态 |
| 成员／门槽／内部引用 | 按目标关系更新同一主体映射；建立目标前不保存悬空原生借用 |
| 几何／碰撞／路径／邻接 | 由目标布局及对象状态更新原生对应数据和必要缓存；只改画面不算完成 |
| 背景／水／颜色／光照／FX | 设置原生Room与对应环境状态，调用明确所需的原生刷新，使游戏资源和渲染反映目标 |
| 不能由恢复状态唯一得到的外观 | 向原生对象补充实际变体／资源选择、动画或必要姿态值；仍由原生对象管理和渲染 |
| AuthorityOnly／只读派生语义 | 保留其归属；只读派生量用作一致性条件，找出决定它的状态或必要恢复入口，不假造通用setter |

普通change不重复完整Init，不为了刷新外观运行整个Room或Grid玩法Update。若某类型必须经过混合函数维护外观，须在Client复制应用上下文中只允许必要维护部分，阻断其玩法裁决；不能单凭函数名决定允许或禁止。

若原生状态转换不可原地逆向恢复，例如目标从破坏后态回到完整态，允许按该类型恢复合同重建本地载体并保留逻辑key。不能因为本地只能正向执行动作就拒绝服务器合法最终状态，或通过再次触发玩法来补齐状态。

邻接外观可能受create／remove／change共同影响。记录本次受影响对象及相邻对象，在结构应用后批量刷新其原生缓存，避免只刷新改动格导致大岩石、坑边缘或门墙连接残留。刷新范围依具体类型，不增加第二套布局／贴图生成算法。

## 4. 同步调整17：保留原生展示，隔离玩法

17当前Client会跳过原生世界绘制、调用自有`PresentationDraw`，并抑制Game／Room等更新。仅增加18的状态setter无法使原生对象自动显示。**17的运行时接线调整是本tx的必需工作，属于18完整实现及整体验收。** 17既有隔离、线程和资源寿命事实继续参考；其受控Scene通过结果不能自动覆盖新的原生路径。

| 边界 | 本次处理 |
| --- | --- |
| Host／Off与Hook | 保留原生行为；Hook继续唯一清单注册、启动安装后常驻，Client会话只逻辑启停 |
| Client状态应用 | 主线程进入有界的复制应用上下文，允许明确的对象建立、恢复、移除及资源维护；退出时还原逻辑上下文，异常也必须退出 |
| Client常规运行 | 网络目标驱动状态，不运行独立AI、伤害／碰撞裁决、拾取、掉落、机关裁决、切房裁决或玩法随机；保持输入采样上行 |
| 外观准备与渲染 | 调整原生世界绘制分派，保留合法Room／Grid所需PreRender、资源／缓存维护、相机、动画及原生render；只处理这些实际保留路径中的具体副作用 |
| Lua与初始化回调 | 不重放gameplay回调；必要本方适配与原生资源维护按明确上下文开放，不能因当前通用Lua全部冻结而改为外置重画世界 |
| 持久行为 | 保留17的PGD／Continue／成就／统计／Mod持久保护，载体建立与退休也在保护窗口内；不回滚dirty掩盖非法写入 |
| 未完成／应用失败 | 未有有效载体或正在变更时保留等待／失败界面，不绘制无效原生世界，不因失败放开本地玩法 |

初始化和外观维护中的随机用途须具体区分。玩法结果仍由Authority给定；资源初始化若内部使用随机，须明确其对象、输入与作用范围，通过Authority选定的变体／参数或隔离的表现初始化保证外观，不能推进另一份玩法随机历史，也不能以“所有RNG绝对零调用”禁止必要原生资源初始化。

同样，渲染缓存／临时状态写入可以是正常原生维护。判断依据是是否改变权威玩法语义、对象存在性或持久结果，不能因为函数不是纯函数就将整条原生渲染树排除。

有动画事件的路径须防止事件再次触发玩法；动画的状态转换、目标阶段及暂停来自Authority。明确允许的本地表现插值／动画推进不获得改变Grid玩法State的权限；跨端动画时钟与平滑扩展仍与27／32衔接。

## 5. 来源、接口与提交顺序

复用现有正式观测consumer及15的Registry／DTO。Authority采集不依赖Recorder、测试控制口或渲染资源截获。Client后台只重组自有值并排队；原生指针、对象和Lua操作全部留在已理解的主线程窗口。

建议保留最少的职责边界，不新增通用渲染框架：

- `replica`层：从完整目标与最后成功应用目标生成Room／Grid三语义计划，不依赖SDK；现有15模型／codec继续作为数据入口。
- `game`层：管理原生Room载体和Grid key→本地对象关系，执行具体create／remove／change与必要原生刷新。
- 17现有Client边界：提供应用期间停显、原生展示分派、玩法／回调隔离及正常退出；16保持网络角色／输入入口。

同一个正式应用入口接收完整重建后的Room／Grid目标，返回域版本成功、需要恢复或具体失败原因；E2E调用该入口，不另写测试专用应用器。真实网络重组、调度与整世界Applied ACK在21／22接入，18不得以测试命令读JSON的能力冒充正式来源已经接线。

一次域目标的执行顺序为：

1. 检查scope／新旧revision，完整解码目标、配置／资源依赖、448格及八门视图和引用；在纯值阶段拒绝未知／不完整候选。
2. 暂停本方世界展示和原生对象消费，在正确主线程窗口进入复制应用上下文；确认载体仍属于当前scene。
3. 准备／恢复必要Room结构及环境上下文；清理失效引用，移除阻塞目标位置的旧主体，再创建缺少的目标主体。
4. 应用全部目标字段／关系，恢复门别名、派生状态及必要外观；更新受影响的几何、碰撞、邻接及环境缓存。
5. 从实际原生对象检查关键状态与成员已成立，提交域revision／本地目标C，恢复原生展示资格。
6. 原生阶段若部分失败，记录已执行范围，保持停显及玩法隔离，清理并请求完整恢复；不发布成功，不承诺旧原生世界仍完好。

这里不假定原生写入可任意回滚或同时维持两个完整Room。纯值候选拒绝可保留未改动的旧世界；进入原生变更后的失败按停显恢复处理。18的成功只表示Room／Grid域应用，不能置整世界Applied或代替19／20对象应用。

18内部Room／Grid引用必须实际解析。指向Entity／Player等其他域的引用保留规范key及明确依赖，与19／20适配器衔接；没有实际目标时不写裸地址或伪造null，也不宣称跨域世界已完整应用。载体需要合法的空Entity容器等结构，不依赖尚未实现对象的悬空指针。

## 7. 实现前失败模型

- create只有类型／seed、没有完整当前后态，导致晚加入把残骸、已开门或桥恢复成初始状态。
- 重复create生成两份；相同index误认同ID；门别名双重创建；不兼容类型只改Type造成对象布局错误。
- 把破坏状态误当remove，或用Destroy执行remove，额外产生掉落、统计、音效／事件或其他实体。
- 延后移除仍占槽；即时移除后残留门视图／引用；邻接缓存只更新当前格，留下错误坑边／岩石连接。
- change修改数据但没有必要外观刷新；为刷新调用整Room／Grid Update，推进机关、奖励、计时或玩法随机。
- 描述恢复覆盖当前状态；Init每次change重抽变体、重置动画或触发回调；使用本地Room／Manager时间代替Authority计时。
- 只有shape标签、背景ID或同seed，没有实际布局与资源选择；本地构建再次选择不同装饰或玩法结果。
- 17仍跳过原生绘制导致对象不可见；整体放开Game Update又形成第二份Authority；过宽回调屏蔽同时阻止必要初始化。
- B到T的差异被直接patch到C，状态回归基线时旧值残留；旧包覆盖、新包缺字段被当删除、Partial成员误删。
- 原生半途失败后继续展示／ACK，或假称自有DTO原子替换意味着原生世界也已回滚；旧scope对象被新scene复用。
- 网络线程持有对象，应用与render／退休交错，外部引用悬空；正常stop恢复玩法过早或触发访客持久写入。
