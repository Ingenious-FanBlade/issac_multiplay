# tx-04-18：Room／全部 Grid 客户端应用实现计划

日期：2026-11-02，Asia/Singapore。状态：**I01—I06已实现、完成静态主审并纯构建成功；I07—I30及G01—G27待实现，统一实机验收未执行。** 初稿只编写计划，用户随后启动I01—I06；具体代码、来源、Luna研究与主审纠错见[基础实现说明](tx-04-18-foundation.md)，逐成员应用映射见[功能目录](room-grid-application.json)。

本次目标是把正式复制模型中的活动房间构成、环境、门和全部原版 Grid 类别，应用到真实 Client 的原生世界，支持创建、改变、替换、移除及失败后的安全退休。本文逐项列出实现内容、注意事项和完成判据；[全部 Grid 逐类任务](tx-04-18-grid-application.md)是本计划的组成部分，不能只完成公共接口就结束本 tx。

执行依据为[现行项目规范](../../refactor/project-conventions.md)；任务边界见[完整路线图](../state-synchronization-roadmap.md)。I01—I30、G01—G27、E01—E18只是同一个 tx 内的工作／验收索引，不是新 tx，也不设 gate、哈希校验或角色分离要求。

## 1. 交付范围及已存在的基础

### 1.1 本 tx 要交付的实际行为

1. 真实 Client 从菜单冷构建服务器指定的活动房间，不运行同 seed 本地游戏生成布局，不借用之前在本进程运行过的 Host 世界。
2. 安装正确的 RoomDescriptor、Data／OverrideData、房形／几何／布局、背景／环境和必要展示上下文；支持同一房间内状态变化及需要重新构建承载的目标。
3. 应用 GridEntityType 1—27、全部 17 个公开派生接口的相关状态、保存描述、资源和成员关系。0 是空类型，不构造对象；未知类别明确报告，不能当作空格。
4. 门的实际 Grid 主体、Room 门槽引用、形状允许、descriptor 启用位和目标关系分别正确；没有实际门不等于没有邻接候选。
5. 正确处理同格替换、相邻格缓存、跨域引用、短命变化和部分失败；任何已发生原生写入的失败均不得继续显示或确认半套目标。
6. 保持唯一 Authority、Client 玩法与访客进度隔离、主线程／资源寿命及统一输入语义；生产应用不依赖录制、日志或测试 Lua。

“全部 Grid”指本 tx 的类别和接口合同必须实现。各类仍要按已知专用分支建立代表性场景；所有原版变体、角色／物品／路线组合的联合覆盖归 29，不能把缺失的 Grid 类别、必要字段或基础生命周期推到 29。

## 2. 字段、身份与接口用语

### 2.1 不使用含混的“房号”或“特殊 descriptor”

| 字段／接口 | 在本计划中的含义 | 必须区分的情况 |
| --- | --- | --- |
| `Game::_currentRoomIdx`／`Level:GetCurrentRoomIndex()` | 当前房间入口所在的楼层网格索引，或已定义离图索引 | 大房进入象限可不同，不能直接等同 `GridIndex` |
| `RoomDescriptor.GridIndex` | 楼层13×13布局中房间占位的左上象限索引 | LTL 的该象限可能恰好是缺口；离图记录使用对应特殊索引 |
| `RoomDescriptor.SafeGridIndex` | 能定位该房间实际占用象限的索引 | 不能用它覆盖入口象限或直接当唯一身份 |
| `RoomDescriptor.ListIndex` | 当前楼层 descriptor 集合中的位置 | 与 GridIndex 不同；跨维度的当前集合可区分，跨楼层／重构仍需稳定 Key／代次 |
| `RoomDescriptor:GetDimension()`／目标SDK的 `Dimension` | descriptor 所属维度 | 不用当前房间维度替代全部记录的维度 |
| `RoomDescriptor.Data`／`OverrideData` | 布局配置与替换配置 | 如 miniboss 替换，两者不保证相同；两者都不是运行时完整成员清单 |
| `GridEntity:GetGridIndex()` | 活动 Room 内的格子索引 | 与以上楼层网格索引完全不同，最大容量按目标原生数组核定 |

原版 [RoomDescriptor](F:/projects_isaac/IsaacDocs/docs/RoomDescriptor.md)明确解释上述差异；[GridRooms](F:/projects_isaac/IsaacDocs/docs/enums/GridRooms.md)提供 ERROR 房索引判断示例。离图房间仍使用同一个 `RoomDescriptor` 类型，例如 `ROOM_DEVIL_IDX=-1`、`ROOM_ERROR_IDX=-2`、`ROOM_DEBUG_IDX=-3`、`ROOM_DUNGEON_IDX=-4`、`ROOM_BLACK_MARKET_IDX=-6`、`ROOM_GENESIS_IDX=-12`。`-100/-101`是镜子／矿道门路由哨兵，不可当真实 descriptor 地址索引；`NO_ROOM_IDX`、数量常量也不是对象。

REPENTOGON [RoomDescriptor](F:/projects_isaac/REPENTOGON-1.1.3/docs/docs/RoomDescriptor.md)扩展了维度、邻接、Doors、保存集合和有效 AllowedDoors 读取，没有另创“特殊 descriptor”类型。`LRoomAreaDesc`、`LRoomTileDesc`、`RailManager`等是Room关联结构，不是RoomDescriptor子类，也不据此推定存在另一种Room派生类；按I12的实际接口处理。

### 2.2 所有任务共享的合同

- `T`为完整不可变目标，`A`为最后真正原生提交且仍有效的状态；纯值 Stage、资源加载成功和某个 Grid 步骤完成不代表整个目标提交。
- Grid 稳定 Key、房间稳定 Key、本地实例代次、原生格子索引分别记录；地址、seed、slot、ListIndex都不能单独作为网络身份。
- `Null`、空集合、字段缺席、明确删除、Unknown、Unavailable、Partial、Truncated分别处理。只有来源声明完整的成员集合可以由缺席规划删除。
- 必需字段缺失或未知不能补0。纯展示派生值仅在输入完备、算法及副作用已明确时本地计算，并记录其输入和失效条件；玩法结果只能来自Authority。
- 允许调用经过理解的公开 setter／构造／维护入口；“目录归属AuthorityOnly”表示不能把该操作当网络RPC，并不表示本地adapter不能为安装最终值使用安全的底层操作。具体是否采用仍须理解副作用。
- 若需要图形／Lua／原生对象，使用17已有用途借用和主线程边界；后台只处理自有值。不得补跑完整 Game／Room／Grid Update 来修缓存。
- 新功能、核心函数和数据结构写中文注释，说明来源、owner、修改范围、失败前缀及退休责任。

## 4. Room及公共接入任务

### I01：逐成员应用归属与覆盖目录

**实现内容：** 以11的 `grid-catalog`、12的 `room-level-catalog`、实际schema和15的归属目录逐项建立应用映射，覆盖继承字段、别名、参数查询、资源子树、回调、结构成员及未暴露需求。每行列来源／版本、语义、应用任务、状态或操作归属、本地承载、依赖、缺失处理、实现位置和最终E2E场景。派生查询明确是由目标基础值派生、保留纯值结果，还是原生展示确实需要相应缓存。

**注意事项：** 不把所有Getter都变成一个setter；`Destroy/Hurt/Reward/Update/SaveState/InitSeeds`等不成为远程调用。别名归一但保留原目录对应关系；不能以一行“通用字段已支持”覆盖未处理字段。真正属于24／25／27的内容列出具体消费责任，18展示需要的前置不能一起后移。

**完成判据：** Room／Grid每一项目标语义都有明确处理与责任，无必需字段被静默忽略；映射可定位到具体实现及同一整体E2E项目。新增应用映射属于功能文档／代码数据，不是每tx artifact。

### I02：补齐必要的正式观测与模型缺口

**实现内容：** 对I01发现的实际需求补来源，例如环境最终缓存、Grid邻接／桥接关系、TimerPlate的可空Sprite资源、原生展示依赖及配置版本。优先公开Lua字段／Getter；只在公开来源不足或副作用不明时读目标源码／补必要逆向。扩展正式consumer和schema，使Client可从生产采集得到同样数据；需要新增必需语义时同步模型版本、能力及未知值处理。

**注意事项：** 原始种子不等于最终随机结果；不得额外抽奖、创建状态表或推进动画来读取。独立Render／Lifecycle与普通完整窗口保留各自scope／依赖，不拼成原子快照。`GetRenderPosition`沿用11已经规避官方临时Vector泄漏的来源，不重新引入泄漏wrapper。来源缺失如实报告，不能由E2E临时补写替代正式来源。

**完成判据：** 每个新增必需值有正式来源、有效性及失败语义；无来源的功能仍列未完成。未来验收可证明关录制后目标仍能交付。

### I03：Room／Grid纯值目标和能力声明

**实现内容：** 在15模型之后增加领域解析层，建立有界 RoomTarget、GridTarget、GridDescriptor、RoomLayout、DoorBinding、EnvironmentTarget及资源／引用描述。名称可在实现时调整；内容须包含Scope、component版本、稳定Key、成员完整性、类型／variant／状态和每项required依赖。解析后目标不可变；模型层、SDK边界和线程间值相互分离。能力声明包含具体类别、字段／资源合同和预算，不再以17代表profile代表本tx能力。

**注意事项：** 不重复建立Entity／Grid身份系统；同门在room与grid只是一份主体。引用类型、整数宽度、位标志、数组边界、非法路径及非有限数均在写前处理。无效目标不修改A；协议兼容变更显式声明，不静默放宽旧profile。完整源模型与本tx范围投影分别保存语义，投影不能改变原来源coverage。

**完成判据：** 相同正式模型可产生确定的完整领域目标；未知required成员有字段／key级错误。后续21可以接入同一解析器，而非重写一条网络专用应用链。

### I04：所采用原生操作的必要静态研究

**实现内容：** 对实际使用的Grid工厂、Init／PostInit、即时移除、Door绑定、Room配置／特殊子结构、缓存维护、派生Render与析构逐个明确参数／返回、调用约定、对象前置、官方Hook链、原生发布时点、随机／生成／Lua／持久副作用及失败清理。可复用17 R1—R5的事实；只补其未覆盖的具体J273路径。研究直接归对应adapter，不另拆研究tx。

**注意事项：** Wiki存在API不证明其调用适合Client；`RemoveGridEntityImmediate`仍须处理PathTrail、KeepDecoration、门别名及在途引用。不能将“读过入口”写成整个间接调用已解释。J460偏移只作索引；不校验任何哈希，不进行试跑／probe。

**完成判据：** 每条实际采用路径有可读源码／函数／必要RVA依据、允许用途与异常后责任。具体未知必须在本tx实现中解决或明确保持功能未完成，不能用猜测落写。

### I05：A→T计划、依赖、取消与替换策略

**实现内容：** 基于不可变T和有效A生成Room保持／修改／重建、Grid create／change／replace／remove、引用修复、资源与缓存失效计划。区别同Key换实例和同格新Key。建立依赖关系：几何先于格子、构造依赖先于字段、完整邻居后再收敛邻接、真实Player先于需要Player的Backdrop收尾。提交保留原子可见性，底层可分步执行。

**注意事项：** 不固定为“所有Grid都必须在所有Entity之前”；桥、门、环境对象按实际依赖。写前取消可以保留A；发生写入后不能拿A旧副本冒充原生回滚。新目标到达不在执行一半的旧计划中直接替换参数；明确完成／取消／退休规则，控制待处理目标数量。

**完成判据：** 重复目标、旧目标、回到旧值、同格替换、目标被取消和依赖不满足均有确定处理；完整事务仍由17场景协调器拥有。

**完成判据：** 上限和超限行为可解释，稳定目标不重复全图创建／加载，主线程不等待网络或慢consumer；复杂合法场景有实际覆盖，完整性能优化留32。

## 7. 实现前失败模型与统一E2E清单

### 7.1 必须在实现中处理的失败方式

| 失败方式 | 必须实现的处理 |
| --- | --- |
| 旧Scope／旧revision／同版本不同目标 | 写前拒绝；重复已提交目标幂等，不重做原生构造 |
| 来源Partial／缺字段／未解析必需引用 | 不把缺失补成空值；等待有界或明确失败，不提交完整目标 |
| 当前索引、GridIndex、SafeGridIndex、ListIndex、Dimension混用 | 写前依据各自语义定位；越界、路由哨兵、Online槽拒绝，合法离图索引正常接入 |
| L形缺口、非法门槽、重复Grid占位 | 解析／计划阶段拒绝冲突，保持旧A；不借坐标钳制掩盖错误 |
| Data／Override不一致或资源重载换代 | 正确处理双配置及其寿命；缺必需配置明确失败，禁止猜代 |
| Grid构造已写槽后Init／资源失败 | 标记真实前缀、撤展示／A有效性，按owner退休／重建，不重复Init碰运气 |
| 同格替换后旧副表／旧借用晚到 | 实例代次校验；退尽旧使用再发布新实例，旧清理不能污染新实例 |
| 删除引发残留Door／邻居指针或TimerPlate旧Sprite借用 | 统一对象引用及资源借用失效处理，不能仅清一个数组 |
| 资源已加载但图层／深度／水裁切错误 | 实际画面仍判失败；修正pass／资源使用，不能只补字段检查 |
| 客户端重复开奖、伤害、RNG、保存或游戏回调 | 在原生入口前按用途隔离；统计实际调用与副作用，不靠结束时恢复数据伪造安全 |
| 目标应用中停止、失联、关闭窗口、换VM／context | 撤新工作、保留实际前缀、正确owner退休；未安全时保持Client隔离，不假称Off |
| 超预算／多目标积压／重复资源重建 | 有界排队和显式结果；不阻塞Authority，不截断必需世界后报成功 |
