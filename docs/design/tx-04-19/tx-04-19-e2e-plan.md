## 1. 目标与统一入口

在19全部功能、17／18必要接线、正式来源和生产应用器完成后，使用一个统一入口验收整个tx。计划入口为`scripts/accept-tx-04-19.ps1`，本轮不创建或执行该脚本。构建及E2E编排在届时统一验收中完成，不拆为类别预跑、smoke、单元测试、独立probe或另一个tx。

实现工作按[10项任务及实施路线](tx-04-19-native-entity-plan.md#101-实施路线与依赖)推进；其中R19-10负责编写本计划对应的统一入口、场景和实际读回，相关测试代码随实现准备，运行验收只在R19-01—09全目标及本入口接线完成后进行。任务与场景的对应表不表示逐任务提前测试。

验收目标是：真实Authority的非Player最终状态使真实游戏Client建立正确原生对象、成员、引用及可见结果，正常维护／退休，并且不形成第二份玩法世界。分类、排序、遮挡、阴影和多pass使用游戏原有机制；验收发现具体缺失时只修对应状态、维护或接线。

用户进一步决定并澄清：**无论飞行还是非飞行，空间阻挡及不阻挡均由Client原生应用判定和处理；Authority同步所需状态并裁决其他效果。** 按[实现合同第7.2节](tx-04-19-native-entity-plan.md#72-client原生空间阻挡与authority效果裁决)，E19-27—32验证真实Entity—Grid交互；不能以“碰撞字段读回相等”“全部碰撞被屏蔽”或等待Authority逐次放行代替Client原生阻挡。

本计划的E19编号只是同一整体验收中的场景索引，不是新增推进编号或逐项启动要求。不得将未执行、未观察、Unknown、Partial或工具失败计为PASS；需要的正常类别或依赖未完成时如实报告整个19未完成。

## 2. 执行方式、配合与实际授权

统一入口编排真实Authority场景和真实Client应用。可以在工具支持范围内并行两个真实游戏实例，也可以先连续采集Authority目标、再在真实Client受控投递；实际采用方式须明确报告。后者属于19域验收，不能写成21的四端实时网络闭环。

每次实机启动前分别告知：当前启动的角色／目的、用户需要完成的操作、何时停止手动输入以及后续自动接管范围。需要跳过开场或其他手动配合时，先确认用户已准备好再启动；续测和连续执行不取消这一要求。已有会话实际授权继续有效，文档本身不提供新的输入、注入、存档或持久写入授权。

执行前阅读并复用18统一入口的部署、启动、控制和正常恢复方式。工具能力不足时补齐本tx必要编排并说明限制，不能以Rust假客户端、另一份应用器或手工写Client字段替代真实游戏。测试专用Lua只在Authority制造场景，不作为发布模组或生产采集来源。

## 3. 数据链与判定方法

### 3.1 正向来源

完整链路为：真实Authority操作／自然变化 → 正式观测consumer及同窗口必要上下文 → 共享Registry和15 DTO／codec → 指定B重建T → 生产应用器从C调和到T → 原生读回与画面观察。

每个正常场景保留临时的真实源scope、key、shape revision、实际类型／变体、当前状态和预期依赖，不能按夹具请求值伪造实际返回。顺序投递所需connection绑定通过明确的接收／投递上下文处理，保留原source事实；不任意改写游戏状态、主体身份或scope后冒充原始来源。

必要Owner载体使用Authority已声明身体及相同Entity key，至少覆盖多Owner和同参与者不同身体；不能用单一默认Player或假指针代替。跨域所需Room／Grid／Owner状态与目标版本依赖相符，不拼接不同时刻的latest值冒充同tick完整目标。

### 3.2 实际应用与可见结果

每类均检查四个方面：

1. **对象与成员**：读取实际原生对象类型、受管key映射、成员与去重、存在性和退休状态。不能只读取应用器保存的JSON。
2. **字段与引用**：从实际对象的适用公开Getter或必要窄只读适配核对公共／专用值、实际引用目标及资源／姿态；另行读回原生空间约束的实际位置／必要运动分量、飞行／碰撞状态和Grid版本，与保留的Authority原始目标分别核对；读回不得再次触发玩法。
3. **原生显示**：观察真实Room／Entity原生绘制的当前位置、形状／曲线、外观、遮挡、阴影及相应pass；原本不可见的实体按其实际原生语义检查，不强行增加显示。对具体可控场景可使用截图／像素辅助判定；不要求整帧逐像素一致，也不以平均画面相似掩盖缺对象。
4. **隔离与寿命**：在创建、变化、连续绘制、移除及退出整个窗口观察额外实体、玩法／Lua／随机和持久行为；同时核对资源及在途借用退休。

整数、枚举、flags、key和成员按合同精确核对；浮点按字段真实存储精度或明确转换制定判据，不使用全局宽容差。不可读／缺失不当相等。E2E可显式开启详细诊断，生产默认不开启逐tick／query或每consumer重复全图读回。

18的参考画面曾隔离全部Entity，其结果只能说明原范围。19的参考必须包含本次受验Entity及必要环境／Owner上下文；不能沿用“全部隐藏Entity”的参考方法通过本次实体画面。若限制比较区域或屏蔽尚非本次范围的Player外观，须明确范围，并实际检查其对实体光照、引用和显示的影响，不能遮掉被验对象。

### 3.3 负向输入

负向用例可复制真实源目标后显式注入缺字段、错scope、未知类、错误引用／资源、冲突版本、超预算或应用阶段故障。此类输入只判定拒绝、停显和恢复，不能用于证明正常类别或视觉正确性。

故障注入仅限显式E2E开关、有界且可正常停止；不破坏未知内存、不制造未理解的ABI调用，也不把人为崩溃当正常失败恢复。本文第5节与实现文档F01—F24先于代码定义失败方式；不另写实现后的单元测试。

### 5.1 Entity与Grid交互的共同判据

E19-27—32按下列41个子用例展开，仍属于32个主场景组的同一tx统一整体验收，不另建脚本入口、推进编号或提前批次。每个子用例可以包含多种实际类型和正反对照，不能以一个子样本代表整行完成。

每个实际交互至少关联：Authority源scope／时间、Entity key／shape revision、Grid key／槽位／revision、普通位移或重定位语义、碰撞类别／大小／飞行状态、交互前态、实际接触或作用的依据、交互后态与对应Client提交版本。没有合法公开源Grid关联时保留Unresolved，不根据位置或同槽猜历史身份。

判定分为三个相互独立的结果：

- **Client原生空间结果**：飞行和非飞行均经过实际原生空间处理；应阻挡时得到原生约束，应通行时实际通过。不能仅以停在远离障碍的位置、最终坐标已由Authority修正、没有运动请求或原生调用计数证明阻挡正确。保留必要原生输入／返回及实际位置／运动分量，和源原生语义核对。
- **Authority效果结果**：真实接触、攻击或机关作用产生的Entity／Grid状态、存在性、引用、产物与短命表现被完整应用；Client不再次施效。不以直接改HP、State、Destroy或手工生成掉落替代“交互确实发生”的正向来源。
- **隔离与恢复结果**：接触期间、后续连续绘制、重复目标和恢复均无额外伤害、减速、反弹、机关、爆炸、随机、奖励或掉落；逻辑T／C和基线不被本地空间修正覆盖。

必须同时有有效与无效对照，例如相同障碍的阻挡／通行、可破坏／不可破坏攻击、机关接受／忽略的主体、免疫／受影响条件。预期来自真实Authority原生过程及适用公开语义，不能套用“全部Entity都受同一Grid作用”的假设。效果有冷却或延迟时检查实际时序和次数，不要求所有结果在同一tick立即完成。

Authority夹具可以用适用公开API建立场景前态，例如Grid种类、位置、大小、碰撞类别和flags；被验的阻挡、命中或施效仍须由真实原生交互产生。前态准备与被验动作分别记录，避免把允许的场景设置误当作用已发生。

截图只辅助观察，不作为Client输入。E2E可显式启用生产路径的窄观测，wrapper保持原调用次数；不为验收单独写另一套阻挡／施效器。适用公开回调、生命周期与实际前后态可共同证明触发，不要求为了每个成员重新逆向。数据不足以区分真实触发与未触发时，记录未完成并补必要来源，不按“看起来没问题”通过。

## 6. 统一执行、失败修复与续测

统一入口可以按以下顺序编排，同一游戏生命周期内合并适合合并的场景，不预设必须启动多少次：

1. 在统一验收中完成必要构建与临时部署，取得每次启动所需配合，建立真实Authority来源。
2. 连续执行类别与关系／姿态场景及第5节的真实Entity—Grid交互子用例，生成正常真实目标、实际触发／前后态及必要参考。采集时不调用有副作用的Getter补值。
3. 在真实Client经生产入口应用目标序列，并执行版本、拒绝、故障、完整恢复和共享场景用例，核对实际原生状态与画面。
4. 在应用全过程观察隔离、预算、资源和输入；完成stop／重连代次／正常退出及部署恢复。
5. 根据实际覆盖和失败修复说明结果，清理正常测试临时材料，更新文档完成状态。

发现失败先定位和修复，在同一tx的整体验收中继续必要测试，不因一次失败默认停下等下一条用户指令，也不另换tx。续测覆盖修复影响及尚未执行项；未受影响且来源／实现仍适用的通过项可说明依据后复用。来源／schema／适用语义改变时，不能继续拿不适用旧目标或18隐藏Entity参考判定新路径通过。

用户要求停止、缺必要配合／授权或存在不能自行解决的阻塞时才中断，说明实际进度、问题和继续条件。中断且确需恢复信息时只保留必要材料，并标明位置／用途；正常测试临时数据用后清理，不要求日志包、源码快照、截图归档或最终artifact。
