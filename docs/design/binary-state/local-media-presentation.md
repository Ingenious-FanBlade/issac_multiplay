## 1. 总原则与当前边界

- 尽量只传游戏状态、实际资源选择、文字、有限显示描述和音频控制事件，由各端使用已安装的原版／官方扩展资源本地显示与播放。
- 原始媒体包括图片文件、纹理像素／压缩纹理、音频文件、PCM及音视频流。压缩、改走Context、改称blob或recipe中的内嵌字节，都不改变其原始媒体性质。当前不启用通用原始媒体传输，也不以它作为来源缺口、冷连接或本地加载失败的自动兜底。
- 资源声明仍表达固定资源空间、规范路径／配置身份、实际选中图像／sample、动画与shader选择、必要依赖和整数版本；资源声明不等于发送资源文件。原版资源安装是各端本地条件，本轮不新增资源下载系统。
- 现有纯值recipe仅承接有限、完整的显示描述，依赖本地资源；优先复用已有状态／参数，避免逐帧全量绘制命令。不得携带任意GPU命令、函数地址或未登记媒体字节。
- 个别原版内容若仍无法由本地资源及有界描述重建，须列明具体用途、缺少的参数／来源、替代办法和实际带宽成本。当前未采纳原始媒体传输例外；不能将“存在Image”直接推导为必须发像素，也不能无声删除必要内容。
- Host仍是唯一玩法Authority。本地生成仅限显示／音频执行，不运行玩法Update、随机掉落、存档／解锁、完整ShowHallucination、ChangeRoom或第三方Lua。原C/S隔离、线程、资源owner与Hook常驻规则保持。

## 2. 横幅、fortune及其他文字：传文字，本地排版

当前路线为“Host封存实际文字与必要显示描述 → 二进制消息 → Client纯显示排版／缓存”。不传HUDMessage.text_image、fortune_image等缓存的像素；不为采集额外调用Host UpdateTextImage。

| 内容 | 网络职责 | Client职责 |
|---|---|---|
| 主／副文字、fortune有序文本行 | 传实际文字，区分空文本、隐藏与来源失败；字符串长度／行数有界 | 使用本地字体排版，文字改变时重建缓存，不按每帧重制 |
| 字体／横幅样式、特殊首码、必要颜色 | 登记有限样式／字体资源标识及必要语义，不能把本地指针或未解释控制码当命令 | 固定adapter消费文字和样式，安全创建自有图像或使用已核纯文字leaf |
| 显示实例与动画 | 保留owner、subject/use/shape、用途、显示代次、当前可见性及必要动画状态 | 保持本端控制组、多人HUD、双身体及本地视口排版 |
| 名称／语言 | 默认发送Host已确定的实际文本，避免Client重新执行道具／概率／玩法查询；字体／语言语义按具名合同补齐 | 不自行把已发送正文换成另一条翻译；字体度量／像素缓存不要求与Host逐字节相等 |

版本61已同源登记DisplayTextRun422、FortuneText423及有限字体／样式编号：严格UTF-8、单串≤2048B、有序fortune≤8行，Prompt保留五个固定文字槽；拒绝NUL／C0／C1及错误Unicode，不将文本作为控制命令。提供已封存UTF-16值的严格转码接口，不读取原生指针；实际wchar_t读取资格、字体映射及特殊首码到有限style的具名映射仍待第10步核定，未知报Gap而不删除或猜测。该决定不改变EntityText既有原始字节串合同。

Client允许执行已核或自有的纯文字显示缓存生成，不因此放行整段HUD Update／Show或调用Lua。文字缓存ready属于本地资源准备；缺少必需文字／样式仍是具体Gap，不用旧缓存冒充新消息，也不回退传图。来源读取、字体／样式映射和安全生成leaf仍待实施。

## 3. 当前Client切房：合法目标就绪后直接切换

当前0—15步不要求Client复现普通切房滑动、旧／新surface混合及其他依赖前后房间图像的平滑过渡；新目标准备并提交后直接显示新房间。不采集／传输前后房间surface，不为了旧房图在Client重新加载或模拟旧房。

- 成员、配置、Room／Grid／Entity／Player、资源及必要HUD仍按完整目标准备和共同提交，目标未就绪时不得提前安装一半新世界。直接切换不等于省略结构事务、生命周期或依赖校验。
- 旧目标仅在其scope/use及依赖仍合法时可展示；已退休时使用本地等待画面等安全显示，不续借旧身份。Authority不等待Client准备，访客不触发原版ChangeRoom。
- Host按原版正常执行切房；本次仅放宽Client的平滑显示要求。必要房间选择、路线、传送、恢复和输入生命周期不变，不要求各端转场画面像素相同。
- Boss versus、Nightmare、死亡／结局等独立语义内容未被整体删除。能用本地Sprite／文字和已同步结果显示的内容继续保留；确与前后surface平滑绑定的效果按本节收缩，不能以此跳过必要剧情或结果。
- 不以缺少Host前后surface阻止目标ACK；ACK仍以本次合同实际要求的状态、声明资源及原生提交成功为准。取消的动画不再创建“必需但永远Wait”的资源依赖。

## 4. Hallucination：本端历史画面生成

采用Client本地生成为主路线：同步world效果有效性、必要强度／颜色／时点、背景变化及其他不可派生参数；Client对自己已经提交并绘制的场景维护有界本地feedback／snapshot，使用本地固定shader合成。Host的Game反馈Image和独立Hallucination Snapshot不作为下行资源。

- 本地snapshot只服务显示，不影响玩法与随机流；本地渲染相位可复用已同步GameFrame／D0，不恢复Host随机生产器。
- 各端视口、分辨率、绘制频率和历史画面可以不同；验收检查效果有效性、参数、生命周期和本地合成行为，不要求反馈像素或历史采样与Host一致。
- 冷连接／重连没有旧历史时，以当前合法已提交场景初始化本地缓存，再按本地显示帧更新；不补传Host历史、不因没有Host snapshot阻塞ACK。实际刷新／冻结／清空规则仍须核定并按本地owner实现。
- 切房、恢复、scope或显示代次退休时撤销不相容缓存，暂停与重复展示不得造成玩法推进。内存、分辨率、缓存数量和图形状态恢复受本地预算约束，后台不持有原生Image*。
- 不调用包含背景变更等副作用的完整ShowHallucination。共享背景变化仍由Host状态下行，Client只执行固定显示adapter。若安全leaf或完整参数仍缺，记为实现Gap，不能据此宣称本地生成已完成或默默关闭效果。

这是一项已采纳的实现方向，完整可行性与观感尚未验证；本次不运行游戏或测试。

## 5. 其他图像与音频

普通道具、ANM2、角色图层及内置shader采用实际资源引用，本地加载。程序道具先核定已有纹理／Sprite／shader组合，再传选中结果和必要描述，不能仅因名称含“程序”就走像素。背景等程序surface优先从本地资源和有界合成描述生成；现有纯值recipe可复用，缺少完整描述的原版用途仍列Gap，不恢复背景玩法RNG／Init或自动退回原始媒体传输。

音频只传实际选中sample／音乐资源标识与必要依赖、voice身份／代次、Start／Stop／Retrigger／Clear、当前Options前gain／pitch／pan／loop／world pause及必要逻辑相位。文件、解码PCM、混音结果和视频音轨不经C/S流传输，Client使用本地资源及非随机播放leaf；同sound多sample仍由Host选定，不能让Client再次抽样。现有voice去重、可靠水位、持续声Baseline、个人音量和设备失败隔离保持，seek／segment及全部逻辑gain来源缺口并未因此解决。

## 7. 失败方式与本次完成内容

- 只换文档名称，仍把纹理／压缩图／音频字节塞进blob或recipe，或在本地资源缺失时自动下载。
- 文字缺样式／字体或错误转码、身体归组错误、旧缓存跨代复用；为生成缓存运行玩法／Lua／整段HUD Update。
- 直接切房提前安装部分世界，或旧surface仍被列为必需依赖而永远不ACK。
- Hallucination用当前world冒充Host历史来源，或本地合成错误触发背景／玩法更新；把允许的像素差异当状态不一致。
- 只传sound ID让Client随机选sample；重复状态重启voice，或把Host静音／设备失败当world Stop。

最初设计修订完成规范、主入口及9—15步交接，未改代码或运行构建。随后版本61已修改第9步正文代码／schema并同源生成、完成Release／Win32状态库纯编译；原生来源事实与失败记录保留，没有运行游戏或任何测试。第15步按修订后的合同统一验收。
