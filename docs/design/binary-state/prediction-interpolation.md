## 1. 问题与目标

### 1.1 现象

2026-11-19 同机联机时，用户反馈客机输入不跟手。客机从按键到看见结果，要经过整条权威链（推算，未实测）：

| 环节 | 估计 | 依据 |
|---|---|---|
| 输入提前量 | 约 33ms（Host 开插值）；约 67ms（Host 关插值） | `input_lead_ticks=2`；Host 开插值时 Authority tick 约 60Hz（RE-P6 勘误，原写“约 30Hz → 67ms”），另加 RTT 与发布年龄的投影 |
| Host 采集、编码、发布等待 | 平均约 22ms，最差约 44ms | r8 World／Body 22.8Hz，编码线程饱和（[最终一致修订 10.7](eventual-consistency-revision.md#107-host-编码线程提速与-body-60hz2026-11-17用户同意未实施)） |
| 客机安装与显示 | 约 16ms | 下一个 Manager 帧安装 |
| 合计 | 约 70—150ms | 同机传输近似为零；阶段 0 计时 `stream.latency.*` 给出实测值 |

另外，客机拦截了原生半帧更新（Odd helper `0x2F9340`），里面含原生插值，所以客机上的实体随 World 约 30Hz 一跳一跳，World 晚到时整个画面冻住。

### 1.2 目标

1. **本机身体跟手**：本机身体的移动在采样输入的同一个或下一个渲染帧内反映到画面和相机。
2. **远端平滑**：其他玩家、敌怪、泪弹、敌弹等在 60FPS 渲染下连续移动，不随 World 30Hz 或到达抖动跳动。
3. **断档不冻结**：World 晚到时，按速度短时外推，新数据到达后平滑并回。

### 1.3 非目标

- 不做 gameplay 预测或回滚：射击、泪弹生成、拾取、受伤、击退、道具使用、开门、换房都不在客机本地执行。
- 不做 Host 侧的延迟补偿（不为客机倒回房间判定碰撞）。
- 不改变 Host 唯一权威、显示委托、方案 B 帧号、最终一致合同和带宽指标。

## 2. 主流做法（参照）

### 2.1 三类对象

| 对象 | 方法 | 效果 | 代价 |
|---|---|---|---|
| 自己操控的角色 | 预测＋对账：本地立刻执行输入，服务器结果到达后从权威状态重放未确认输入 | 操作零延迟 | 客机要跑移动计算；纠正时可能拉扯 |
| 其他实体 | 插值：显示时间比最新快照晚一点，在两份已收快照之间过渡 | 平滑 | 看到的世界晚 1—2 个快照间隔 |
| 数据断档 | 外推：按速度短时向前猜，新数据到后融合 | 抖动时不冻结 | 对多变运动猜错 |

### 2.2 Unreal

- **角色身份**：Authority（服务器）、Autonomous Proxy（本机操控，做预测）、Simulated Proxy（其他人，只插值或外推）。
- **CharacterMovementComponent（CMC）**：
  - 客机每拍把输入（加速度、跳跃／蹲伏等标志、时间戳、本拍时长）存成 `FSavedMove`，立刻本地执行，存进待确认列表，再用不可靠 RPC `ServerMove` 上送；相邻可合并的移动合并后发送。
  - 服务器用同一组输入和时长执行同一段移动代码，与客机报告的位置比较：误差在阈值内回 `ClientAckGoodMove`，超出回 `ClientAdjustPosition`（权威位置、速度、时间戳）。
  - 客机收到纠正：重置到权威状态，丢掉时间戳之前的移动，重放其余待确认移动。
  - 显示平滑：碰撞体直接到位，模型保留一个偏移并按指数或线性衰减追上。
  - 已知问题：本机预测的角色与其他角色碰撞时，对方位置是过去的，顶着对方走会抖。
- **技能与投射物**：GAS 用 Prediction Key 让客机先激活技能，服务器拒绝时撤销同 key 的效果；投射物常用客机“假子弹”，真子弹到达后替换或对齐。
- **UE5**：Network Prediction 插件与 Mover 2.0 把“保存输入、重放、纠正”通用化，仍标为实验性。

### 2.3 Source 引擎

- 本机玩家预测，原理同 CMC。
- 其他实体按 `cl_interp`（默认 100ms，即 20Hz 下两份快照）延迟插值；断档时最多外推 `cl_extrapolate_amount`（默认 0.25s）。
- 服务器对即时命中射击做延迟补偿。

### 2.4 Overwatch 与回滚类

- Overwatch：客机领先服务器约半个往返加缓冲；服务器反馈输入缓冲深度，客机微调本地 tick 速度。
- GGPO、Rocket League：整个世界可存档、可重放，要求确定性。本项目不走这条路。

### 2.5 isaac-lan

2026-11-19 读码（本地 `F:\projects_isaac\isaac-lan`，提交 cb872a8，v0.7.2；只借鉴思路，不拷代码，仓库仍无 LICENSE）。客机跳过原生半帧更新，三类手段都在 Lua 中实现，每次渲染直接把显示位置写进 `Entity.Position`（它每个 tick 全量重写实体，所以不需要写回）。

**本机移动预测**（`src/bridge/presentation/prediction.lua`、`motion.lua`）：

- **输入**：每次渲染在本机房间作用域内调用原生 `GetMovementInput()` 取方向（含镜像等原生规则），不等网络。
- **移动模型**：Lua 复刻原版步行积分，按 60Hz 半帧细分：先乘地面摩擦（`p.Friction`，含减速液），再按旧速度推进位置，最后算新速度。新速度由 MoveSpeed 缩放的输入投影、沿输入方向与垂直方向的不同阻尼、反向加速项组成，常数为逆向拟合值（如滑行保留率 √0.775）。
- **碰撞**：只做地形。沿移动路径以不超过 4 单位的步长扫过，检查身体中心和半径上 8 个点的 `GetGridCollisionAtPos`；大便按圆形边界，石头、墙、坑按格子；受阻时沿可通行轴滑动，碰到的轴速度清零。飞行和联机幽灵可越过坑和障碍。另加 `GetClampedPosition` 限在房内，门口通道单独放行。**不和敌人或其他实体碰撞**。
- **确认**：Host 每份视图携带各玩家“已消费的输入序号”（`inputSequences`）；客机用序号＋状态 tick 确认。收到确认后丢掉已确认输入，从权威位置**和速度**重放其余输入。注释说明序号代表采样状态而非 Host 模拟步数，重放是显示近似。
- **纠偏**：显示位置 = 预测位置 + 纠偏量；纠偏量按 60ms 时间常数指数收敛，且收敛速度上限每秒 120 单位，只限制纠偏分量，新输入照常即时推进。
- **跳变**：权威位置相对上次权威、也相对该序号的预测位置都超过 96 单位时，视为传送，直接重置。
- **上限**：最多保留 120 次渲染输入；未确认输入累计最多推进 500ms，从 350ms 起逐渐减弱输入，到上限停止前进，只有真实确认才能释放预算。
- **资格**：`ControlsEnabled`、`AreControlsEnabled()`、附加动画已结束（拾取、使用、举起道具、吃药、受伤动画仍允许走）、不在门口转场中。角色兼容组件可声明某身体不用步行预测，改用权威轨迹。地下室梯子与横版平台不预测。控制锁定时速度清零，但保留待确认轨迹继续纠偏。
- **过门**：走到门口阈值后停在门口，等 Host 确认目的地，同时本机淡出；锁门在钥匙足够时最多预览 250ms，不调用解锁、不消耗钥匙。淡入期间停止预测和移动输入。
- **附着对象**：跟随身体的武器、激光（路径、终点、命中特效）、被举起的实体与身体共用同一显示偏移；跟随关系由持有链接、类型、父引用和原生跟随开关判断，发射者引用本身不算绑定（`attachments.lua`）。
- **相机**：在预测位置确定后更新。
- **实测**（其 `docs/history/2026-11-08-feedback-intro-motion.md`）：820 个绘制样本、75 次输入切换，发送与预测显示均在同帧，纠偏速度峰值 120。

**远端实体**（`motion.lua` `track`／`sample`，`timeline.lua`）：

- **不加插值延迟**，改为“外推到现在＋纠偏收敛”：以 Host 采集时钟换算的采集时刻为起点，按速度外推当前绘制时刻，最多 100ms；新状态到达时，以当前显示位置与新外推位置之差为纠偏量，按 1/30 秒时间常数收敛。
- **时钟映射**：Host 采集时间戳映射到本地，取近 64 个样本中“最小到达差 − 最小 RTT/2”，过滤排队抖动。
- **NPC 制动**：连续两份权威状态同向明显减速时，估计衰减率并按它外推，收敛更快；转向和加速不猜。
- **断档恢复**：间隔或估计年龄超过 100ms 时，纠偏速度按实体速度限速（至少每秒 120 单位）。超过 96 单位视为传送。
- **动画**：待机、步行与普通泪弹动画按同一时钟最多前推 100ms，停在末帧，不触发动画事件；普通泪弹高度用原生下落参数推进。

**攻击与命中预测**（`attacks.lua`、`attack_prediction.lua`、`hits.lua`）：

- 头部与装扮朝向按本机射击输入即时更新；蓄力武器从权威武器状态重放未确认输入。
- 普通弹道泪弹按本机冷却时钟绘制**独立精灵**（不创建实体、不调射击函数、不消耗随机数）：外观和多发形状从已确认的本角色泪弹学习；权威泪弹到达后按发射者、速度、出生时刻和位置匹配，每颗接管一次，平面位置与高度平滑衔接。
- 命中表现：本机普通泪弹与可受击 NPC 做连续圆形接触检测，接触当帧绘制受击闪烁、暂时隐藏泪弹；Host 事件按来源／目标 ID 确认，否决则撤销，350ms 未确认恢复泪弹。不调用伤害、死亡、AI 或随机数。
- 激光、近战、穿透、爆炸、特殊 TearFlags 不预测，等权威事件。

**与本设计的差异**：见 4.2（我们只发变化字段，需要覆盖层写回）、5.3（它也只预测地形碰撞，与 P7 一致）、6.2（它不用插值延迟，远端全用外推＋纠偏，P4／P5 需据此再议）。

### 2.6 共同结论

1. 服务器始终权威，三种手段只改客机显示。
2. 预测只覆盖“只依赖本地输入和客机已知稳定状态”的部分；依赖服务器专属状态或会产生副作用的结果（伤害、击退、生成）不预测，靠对账收敛。
3. 插值延迟越大越平滑，但世界越晚；需要按抖动自适应，并给传送、出生等不连续情况单独处理。

## 4. 总体结构

### 4.1 三个时间

时间单位统一为**半帧**（1/60 秒），记作 h；Host game_frame F 的 StandardRoom tick 对应 h=2F，OddPlayer tick 为 2F+1（RE-P6：Host 开插值时成立；关插值时没有 OddPlayer tick，一个 tick 含 2F 与 2F+1 两个玩家半步）。

| 时间 | 含义 | 使用者 |
|---|---|---|
| 权威时间 T_a | 最新已安装 World／Body 的 Host 时间 | 原生对象中的字段、方案 B 帧号、离散状态 |
| 世界显示时间 T_w | T_a 的平滑估计减去插值延迟 D | 远端实体的显示位置 |
| 预测时间 T_p | 本机最新已采样输入对应的时间 | 本机身体的显示位置、相机 |

T_p 领先 T_a 约“输入提前量＋往返”，T_w 落后 T_a 约 D。

### 4.2 显示覆盖层

预测、插值、外推都只产生**显示值**，不写入权威状态。实现为一个“显示覆盖层”：

1. **权威值不变**：World／Body 安装照旧把 Host 值写进原生对象；漂移扫描照旧比较权威值。
2. **进入作用域**：在相机阶段和 `Game::Render` 之前，对每个有覆盖值的对象核对地址和实例代次，暂存原字段，写入显示值（本机身体为预测值，其余为插值或外推值）。
3. **原生运行**：相机、Render、Render 期间放行的 Lua 回调读到显示值；Render 写的屏幕坐标缓存 `+0x1A4/+0x1A8` 由显示值算出，这正是想要的结果。
4. **退出作用域**：Render 返回后逐对象写回暂存的权威值。

选覆盖层而不是让客机长期拥有这些字段，理由：

- 安装、漂移扫描、最终一致合同和需求清单都不需要改；
- 预测出错、关闭预测或断线时，退出作用域即回到权威显示；
- 与[显示委托 6.1](client-display-delegation.md#61-借鉴-isaac-lan-排除的逆向点)留下的“在 Render 作用域内做显示插值并在返回后恢复”一致。

覆盖的字段首版只有 pos（必要时加 posOffset），由 RE-P4 确定 Render 和相机实际读哪些位置字段。若 Render 还读原生半帧历史位置（REPENTOGON `InterpolV2` 等补丁相关），覆盖层也要写同一组字段，否则画面在两套位置间跳。

> **RE-P4 结论（2026-11-19）**：Render 只读 pos＋posOffset，不读历史位置 `+0x344`；`InterpolV2` 只插 ANM2 关键帧，与实体坐标无关。原生非玩家插值本身就是奇帧写 pos、偶帧前恢复，与覆盖层同法。单人相机 UpdateUltrasmooth 还读 velocity 做前视，本机身体覆盖时宜同写预测速度。详见 [render-camera.md](prediction-interpolation/RE-P/render-camera.md)。

### 4.3 每个 Manager 帧的顺序

1. 输入采样（现有 `ClientPollInput`），新输入进本机预测（第 5 节）。
2. World／Body 安装（现有），新的权威样本写入插值历史（第 6 节），本机身体触发对账。
3. 显示推进 30Hz 批次（现有，HUD 等）。
4. **进入覆盖层**：计算 T_w，求每个对象的显示值并写入。
5. 相机阶段（现有）。
6. `Game::Render`（现有包装）。
7. **退出覆盖层**：写回权威值。
8. 漂移扫描（现有）只在覆盖层之外运行。

## 5. 本机身体预测

### 5.1 范围

- **预测**：本机身体的位置、速度，以及由此带来的相机跟随。
- **第二阶段（见第 11 节）**：头部朝向和射击方向的显示；本机发出的泪弹出生融合（5.6）。
- **不预测**：射击与泪弹生成、拾取、受伤、击退、减速状态的施加、道具使用、开门、换房、换形态。

### 5.2 本地移动计算

客机只为本机身体执行一段**纯移动计算**：输入 → 速度 → 位置，加碰撞。不放行原生 `Player::Update`（含射击、道具、随机、伤害）。两条实现路线，由 P2 在 RE-P1／RE-P2 之后决定（**RE-P2 结论**：ControlMovement 与完整格子碰撞均有副作用，M-b 只能用于地形查询，速度模型与碰撞响应须 M-a，见 [collision.md](prediction-interpolation/RE-P/collision.md)）：

- **M-a 复刻**：按逆向结果用 C++ 实现加速度、摩擦、MoveSpeed 换算、速度上限，碰撞用自写几何。
- **M-b 调原生纯函数**：若原生移动积分或格子碰撞能单独调用且没有副作用（不触发回调、不改其他对象、不消耗随机），直接调用。

两条路线都要满足：

1. **节拍与 Host 一致**：Host 上 Player 按半帧移动。Host 开插值时每个 Authority tick 只含一个玩家半步，每条输入驱动一步；关插值时一个 tick 含两个半步、同一输入（RE-P6 勘误，原写“输入按两个半帧保持”）。客机每条输入执行同样次数的半帧步，步的边界与 Host 对齐，因此客机须知道 Host 的插值模式。该选项是游戏原生的隐藏设置：启动时由 Manager 初始化（`sub_92BA20` → `sub_8FE1C0`）从 `config.ini` 读键 `EnableInterpolation`，缺省为 1（开），不在 `options.ini` 和选项菜单中，exe 中没有写回该键的代码；对局中只有 Mod 直接改内存才会变化。仍由 5.7 的相位字段逐样本携带“本 tick 半步数”，代价很小，且不依赖握手或观测 tick 速率推断；对账重放每条输入时按该输入所在 tick 的半步数执行。半步内顺序为：摩擦与按旧速度积分 → 由输入算新速度 → 格子碰撞（RE-P1）。
2. **参数取权威值**：MoveSpeed、飞行、碰撞类别、尺寸等从已安装的权威对象读取，不本地推算。
3. **只写自有状态**：计算结果放在预测状态里，不写原生对象（原生对象只在覆盖层作用域内暂时写入显示值）。

### 5.3 碰撞范围（P7）

本机身体处在 T_p，其他实体的已知位置在 T_a 或更早，所以碰撞分三档：

| 情况 | 首版处理 | 原因 |
|---|---|---|
| 墙、石头、坑等地形格子 | 预测 | GridEntity 已同步，变化慢。无 GridEntity 的格子由 `Room+0x76C` 寻路 cost 决定碰撞类别（RE-P2 第 3 节），其阻挡位按 5.3.1 补同步（2026-11-19 用户决定） |
| 静止或很慢的阻挡实体 | 预测 | 延迟窗口内位置几乎不变 |
| 自身速度属性、减速状态 | 预测（读权威字段） | 随 Body／World 同步，重放时直接使用 |
| 被移动中的敌人推挤 | 不预测，由对账纠正 | 敌人位置是过去的；客机也不能推动敌人。实测抖动明显时再加“敌人外推到 T_p 的软碰撞” |
| 击退、受伤 | 不预测 | 取决于无敌帧、护盾、闪避类道具和 Host 随机；接触伤害就在原生碰撞处理里，调用原生碰撞流程会带出副作用 |

没预测到的效果不会丢：对账从包含它们的权威状态出发，只是晚约一个往返出现，再由平滑过渡。

#### 5.3.1 寻路 cost 阻挡位同步（P7，2026-11-19 用户决定）

**背景**：`Room::GetGridCollision`（`0x7E6AF0`）在格子没有 GridEntity 时读 `Room+0x76C` 的 `grid_paths`（i32[448]，即 Lua `Room:GetGridPath`）：1000—2999 与 ≥4000 为 SOLID，3000—3999 为 PIT，<1000 无碰撞。布局原定该表“留 Host”，客机上全为本地值。已知会产生“无 GridEntity 却阻挡”的来源是 Grimace 所在格（3999，每帧重置）和 Lua `SetGridPath`／`FindGridPath` 写入的高值。

**发送内容**：不发原始 cost，只发由它推出的碰撞类别，每格 2 位（0=无、1=PIT、3=SOLID，2 保留）：

- 448 格共 112 字节，作为 Room 记录里的一个派生字段（暂名 `grid_path_block`），由 Host 在采集读取窗口内按上面的阈值从 `grid_paths` 计算；
- 不论该格有没有 GridEntity 都按 cost 计算，客机查询时仍先看 GridEntity（与原生顺序相同），所以有 GridEntity 的格子不受这一字段影响；
- 原始 cost 中 900 的足迹每次衰减 100、950 的火堆不阻挡，这些变化不跨 1000 阈值，派生类别不变，不产生流量；只有 Grimace 出现／消失、Lua 写入高值等跨阈值时才变化；
- 随 World 普通流发送，按字段增量（L8）比较，未变不发。

**客机使用**：

- 客机把 112 字节存入预测自有的影子表，按场景（房间、层、维度）作键，换房即作废；**不写入原生 `Room+0x76C`**。原因：Wiki 说明 cost>0 会阻止在该格生成 GridEntity，写入可能干扰客机的格子安装；客机上其他读这张表的原生代码会改变行为；原始 cost 仍“留 Host”。
- 预测的地形查询为：先读已安装的 GridEntity 碰撞类别（`+0x3C`），没有 GridEntity 时读影子表，再套用 `0x6B1C20` 的玩家规则（门、坑、联机幽灵与飞行越过 PIT）。因为原生 `0x6B1C20`／`0x7E6AF0` 读的是客机本地原生表，这部分查询自写（M-a），不直接调原生。`0x6B1C20` 的玩家规则在实施前补核细节。
- 影子表尚未收到（新房间首个 World 之前）时，按“全无阻挡”查询，误差由对账纠正。

**版本**：Room 布局中 `grid_paths` 的同步决定由“留 Host”改为“原始值留 Host，派生阻挡类别同步”，新增派生字段；与 5.7 的 Body 改动在阶段 2 同一次整数版本加 1 中上线，拒绝混用旧版本。布局文档 `layouts/07-room-level/Room.md` 由布局源生成，随布局源修改重新生成，不手改。

**预算**：变化时 112 字节，稳态为零，计入 World 带宽总额。

### 5.4 对账

客机为每个本机身体维护：

- **待确认输入环**：每条记录含输入序号、目标 tick、输入状态、执行后的预测状态（位置、速度）。上限 32 条（约 1 秒），超出即停止预测（5.5）。
- **显示误差偏移** e：初值 0。

收到本机身体的权威 Body 样本时：

1. 取该样本对应的“已处理输入序号” N（来源见 5.7）。
2. 丢掉序号 ≤N 的记录。
3. **命中检查**：序号 N 那条的预测状态与权威状态在阈值内一致时，不重放，只更新基准（对应 CMC 的 AckGoodMove）。
4. **不一致时重放**：以权威位置和速度为起点，按顺序重放剩余记录，得到新的当前预测状态 P'。
5. **平滑**：e ← e + (旧显示位置 − P')。之后每个渲染帧 e 按半衰期约 50ms 衰减（P4 一并定）。显示位置 = 预测位置 + e。
6. **直接跳**：以下情况把 e 清零、直接显示新位置：误差超过阈值（初值 1.5 格）、换房或换层、传送、换形态、身体角色变化、暂停恢复、预测资格刚恢复。

### 5.5 预测资格

本机身体不满足资格时停止预测，显示权威值（带平滑过渡）。资格由已同步字段判定，具体字段由 RE-P3 列出，至少包括：

- 原生控制被禁用（举起道具、过场、死亡、传送动画等）；
- 房间转场进行中、Host 暂停；
- 特殊控制方式：Jacob & Esau、Tainted Forgotten 本体与灵魂等多身体角色，首版只在 RE-P3 确认与普通身体同规则时才预测，否则不预测；
- 待确认输入超过上限、输入代次变化、会话恢复中。

### 5.6 附着对象与本机泪弹

预测后本机身体相对权威位置有偏移 Δ = 显示位置 − 权威位置。跟随本机身体的对象如果仍按权威位置显示，会和身体分开：

- **附着对象**：Parent 或持有关系指向本机身体的对象（环绕跟班、附着激光的起点、举起的炸弹等）在覆盖层中同样加上 Δ。范围由引用字段决定，具体名单见 [RE-P5](prediction-interpolation/RE-P/attachments.md)。首版只做环绕类与附着激光，其余待实测。附着激光除 pos 外还须平移优化点表 `+0x480`、未优化点表 `+0x48C` 的全部点与 EndPoint `+0x4D8`，Render 后逐项写回。
- **本机泪弹出生融合（阶段 3，2026-11-20 实施，见 11.3）**：Spawner 是本机身体、且刚出生的泪弹，加一个显示偏移，约 150ms 线性衰减到 0，避免泪弹从身体后方冒出。泪弹本身仍由 Host 生成。
  - **勘误（2026-11-20）**：原文写“偏移为出生时的 Δ”。Δ 只是预测领先部分（预测位置 − 最新权威位置）。泪弹显示在 T_w，比最新权威身体还早约 D，再加上 World 与 Body 的时差，只用 Δ 会留下约“移速 ×（D＋时差）”的残差，残差仍随移动方向出现。偏移改为 **身体当前显示位置 − 身体在泪弹出生时刻（第一份 World 样本的 h）的权威位置**。身体出生时刻的位置从客机保存的 Body 权威样本环（每身体 32 份）插值求得。这样，出生点相对身体的关系保持不变，整条轨迹先平移到当前显示的身体旁，再回到权威轨迹。
  - **泪弹不按 Parent 附着**：泪弹（类型 2）一律走远端插值，不进入上一条的附着 Δ。若原版射击给泪弹设了 Parent=玩家（J273 未核），旧判定会把本机泪弹全部当附着对象：跳过插值、按 World 频率阶梯跳动，并每帧随当前 Δ 平移。

### 5.7 对账需要的线上数据

对账要求“权威样本”和“它已处理到的输入序号”出自同一个 Host 时刻。现在两者分属输入 ACK 和 Body 两条消息；RE-P6 核实两者出自同一 Manager 返回窗口，但 Body 段头只有 game_frame，同一游戏帧两个半步同号，客机无法从 Body 本身得知对应的序号与相位，**本节改动确有必要**。方案：

- Body 中每个身体记录增加 `input_processed_sequence`（u32 或 u64 低位）与半帧相位，在同一个采集读取窗口内取值；相位字段同时给出“本 tick 内该身体走的半步数”（Host 开插值为 1，关插值为 2），客机按样本得知 Host 模式（见 5.2 第 1 条）；
- 只对本机身体有意义，但按身体统一携带，开销每身体约 5—9 字节；
- 接受合同整数版本加 1，拒绝混用旧版本。

若 RE-P6 证实输入 ACK 的 `processed_tick` 可以精确换算到 Body 帧，也可以不改线格式，由客机按 tick 关联；但两条消息到达顺序不同，需要额外缓存。推荐改线格式（P3 一并定）。

### 5.8 输入提前量

预测之后，提前量不再决定手感，只决定 Host 能否按时收到输入。首版保持 2；后续可改为“约半个往返＋抖动余量”的自适应值（P8 之后另议）。

## 6. 远端显示插值

### 6.1 历史

- 每个非本机身体的对象保留最近 4 份权威样本 (h, pos, velocity)，来自已安装的 World／Body。Player 的样本在半帧上，其他实体在整帧上。
- 样本只在安装时追加，不从原生对象回读。对象删除或重建时清空。
- 内存：每对象约 4×28 字节；按 512 个对象计约 56KiB，计入客机内存总额。

### 6.2 世界显示时间

- 客机按本地时钟推进 T_w，每个渲染帧加经过的时间。
- 目标值为“最新到达的 T_a − D”。T_w 偏离目标时，以不超过 ±5% 的速率追赶；偏离超过 6h（100ms）或换房、换层、恢复时直接跳到目标。
- **D 的取值（P4）**：基础为一个 World 间隔（2h，约 33ms），再加到达间隔抖动的 p95，限制在 2h—6h。Host 暂停时 T_w 停在暂停帧。

### 6.3 求值

- T_w 落在两份样本之间：位置线性插值。
- **不连续不插值**：两份样本间位置跳变超过阈值（初值 1 格，按速度放宽）、出生、换形态、换房、传送标志时，直接用后一份样本。
- 首版只插 pos（以及 RE-P4 确认需要的伴随字段）；旋转、缩放、颜色等离散或少变的量不插。

### 6.4 离散状态与位置的时间差（P5）

动画帧、生灭、颜色等离散状态仍按方案 B 在 T_a 立即安装，位置却显示在 T_w，两者最多差 D。推荐接受：Isaac 的动画按 30Hz 推进，D 通常只有 1—2 个 World 间隔，肉眼难辨。

另一种做法是整帧延后 D 再安装，离散和连续一致，但所有内容一起晚 D，方案 B 和安装点都要改。不推荐。

## 7. 外推

### 7.1 触发与上限

- T_w 超过最新样本时外推：pos = 最新 pos + velocity × 经过时间。RE-P1：玩家 velocity 按半帧（1/60 秒）计；其他实体按游戏帧（1/30 秒）计，原生奇帧插值的半帧位移为 vel × friction × ts × 0.5。
- 外推上限按类别：

| 类别 | 外推上限 | 理由 |
|---|---|---|
| 泪弹、敌弹 | 200ms | 多为直线或抛物线，外推准确 |
| 敌怪、其他玩家 | 100ms | 走位多变 |
| 拾取物、静止效果 | 不外推 | 很少移动 |

- 超过上限后停在最后外推位置，不继续猜。
- 泪弹和敌弹的高度（下落）首版不外推，只外推平面位置；视实测再议。

### 7.2 融合回真实值

新样本到达后，记录外推显示位置与插值位置之差为偏移，按约 100ms 衰减到 0，不直接跳。不连续条件（6.3）成立时直接跳。

### 7.3 敌弹外推到 T_p（P6）

本机身体显示在 T_p，敌弹显示在 T_w，两者相差“往返＋D”。可以把敌弹单独外推到 T_p，让躲弹判断和 Host 更接近，代价是敌弹轨迹改变时误差更大。首版默认关闭，留作开关供实测比较。

## 9. 实施前列出的失败方式

1. **节拍错位**：客机每条输入执行的半帧步数或起点与 Host 不同，每次对账都有固定误差，表现为持续回拉。对账命中率作为诊断计数。
2. **参数取错**：预测用了过期的 MoveSpeed 或飞行状态，在吃速度道具后持续回拉。参数每步从权威对象读取。
3. **对账样本与输入序号不同时刻**：用 A 时刻的位置配 B 时刻的序号，重放多算或少算一步。5.7 要求同窗口取值。
4. **重放越界**：待确认输入积压（Host 卡顿、网络停顿）导致每帧重放上百步。上限 32 条，超出停止预测。
5. **覆盖层没写回**：Render 异常返回或作用域提前退出，权威字段留着显示值，漂移扫描误报或下一帧求差出错。覆盖层用 RAII 作用域，异常路径也写回；写回前核对地址和代次。
6. **覆盖期间对象被删**：Render 期间对象被释放，写回时写到已释放内存。写回前核对实例代次；若 RE-P4 发现 Render 会删对象，改为只写回仍存活的对象。
7. **漂移扫描看到显示值**：扫描在覆盖层内运行，把显示值当作漂移改回。扫描只在覆盖层外运行（4.3 第 8 步）。
8. **Render 读的是另一组位置字段**：只覆盖 pos，但 Render 用半帧历史位置插值，画面在两套位置之间跳。由 RE-P4 确定字段。
9. **附着对象分家**：本机身体预测后，环绕跟班、附着激光仍按权威位置显示。5.6 的 Δ 传递；范围漏项由实测补充。
10. **插值穿过不连续**：传送、换房、出生时从旧位置滑到新位置。6.3 的不连续判定。

13. **多身体角色控制错**：Jacob & Esau 或 Tainted Forgotten 用普通身体规则预测，另一个身体乱动。首版按 5.5 不预测这些角色，等 RE-P3。
14. **暂停和恢复**：Host 暂停时客机继续预测，恢复后大幅回拉。暂停期间停止预测，待确认输入清空。
15. **预测计算有副作用**：M-b 调用的原生函数触发回调或修改其他对象。RE-P2 必须确认无副作用，否则改用 M-a。
16. **成本超预算**：覆盖层每帧写两遍所有移动对象的位置，加上重放计算，挤占客机主线程。计入单帧预算并单独计时（第 12 节）。
17. **地形影子表过期**：换房后沿用上一房间的阻挡位，或新房间首个 World 之前把空格当阻挡。影子表按场景作键，换房作废，未收到时按无阻挡查询（5.3.1）。
18. **Host 插值模式与客机假设不同**：Host 的 `config.ini` 关了插值，客机按 1 步重放，持续回拉。半步数逐样本携带（5.7），不缓存会话级模式，也不按客机本机设置推断。

### 11.1 阶段 1 实施记录（2026-11-19，仅编译，未运行）

代码：`mod/src/game/client/presentation/client_motion_overlay.{h,cpp}`（逻辑，C++20）与 `client_motion_overlay_native.cpp`（renderEL 遍历与 pos 交换，C++17 SDK 单元）；接入点在 `ClientScene`（`PublishBinary` 采样、`AdvanceDisplay` 求值并经 `ClientDisplayCameraHook` 覆盖相机、`BeginNativeRender`／`EndNativeRender` 覆盖 Game::Render）、`ClientBinaryScene`（World 发布后登记玩家身体与控制组序号）、`client.cpp`（本机序号、Host 暂停、诊断）。产品 DLL `zhlIsaacCS`（`build/repentogon`，Release）编译通过，新文件无警告；未运行任何测试，运行验证归第 15 步。

按设计实现的部分：

- **覆盖层（4.2、4.3）**：只写 pos。每个显示推进先求一次显示值，相机阶段与 Game::Render 各进入、退出一次，共用同一张写入表。进入时暂存原值、写显示值；退出时写回暂存值。写入和写回前都先在 renderEL 中定位地址（先看下标提示、再线性查找）并核对身份，不在列表中的地址一律不触碰（失败方式 5、6）。写入表超过 50ms 未刷新不再使用。Render 的写回在 `ClientDisplayRenderEnd` 的写集纠正之前；漂移扫描在 Manager 的 Pump 中，不与两个作用域重叠（失败方式 7）。显示值与权威值逐位相同的对象不写。

- **融合（7.2）**：外推中途到了新样本时，以旧显示位置与新求值之差为偏移，100ms 线性衰减到 0；偏移超过 1.5 格或时间线直接跳时不融合。

实现时补定、需第 15 步实测核对的细节：

- **时钟**：Host 现在时刻 = 本地时钟 × r − min(到达本地时刻 × r − World 的 h)，取近 64 次 World 到达的最早包络；r 为窗口首尾 Host 帧差与本地时差之比（跨度不足 30h 时取 1，限 0.5—1.5），用于 Host 帧率低于 60 时不持续超前。T_w 每帧按 r 推进，再以不超过 ±5% 追赶“Host 现在 − D”，偏离超过 6h 直接跳。
- **D**：每次 World 到达前，用上式估计“最新 World 样本已过去多久”，取近 64 次的 p95，限 2h—6h。完全规则的 30Hz 下等于 2h，抖动与 Host 漏发都会计入，即设计“2h＋到达抖动 p95”的等价算法。不足 8 次到达时取 4h。
- **Host 暂停**：T_w 停住；恢复后清空到达窗口，重新建立时钟，暂停时长不计入 D。
- **Body 半帧时刻**：Body 段头只有 game_frame（RE-P6），阶段 1 按“同一 game_frame 的第一份记 2F、第二份记 2F+1”推定。Host 漏发其中一份时最多差 1h，阶段 2 的相位字段到位后改用实值。
- **排除对象**：本机身体（控制组序号等于本机 ordinal 的全部身体，多身体角色一并排除）；附着在本机身体上的对象（Parent `+0x3BC` 指向本机身体、跟班 `_player +0x410` 是本机身体、本机身体举起的 `+0x140C`）——它们与仍显示在 T_a 的本机身体同步，阶段 2 再统一加 Δ；**激光一律不覆盖**，留在 T_a。
- **相机**：设计 4.3 的“进入覆盖层后相机阶段”实现为相机调用外的作用域对象，相机返回或抛出都会写回。

已知限制（阶段 1 不处理）：

### 11.3 阶段 3：本机泪弹出生融合实施记录（2026-11-20，仅编译，未运行）

**起因**：用户反馈，客机移动射击时泪弹弹道漂移，与预期偏差太大。静态分析发现两个原因。一是时间线错开：本机身体显示在 T_p（预测领先约 127ms），泪弹显示在 T_w（Host 现在 − D，D 为 33—100ms），两者相差“单程延迟＋D＋预测领先量”，约 150—250ms。原版泪弹出生在 Host 当时的身体位置，所以边走边射时泪弹从身体后方约“移速 × 时间差”处冒出，整条弹道相对身体平移。二是可能误判附着：若泪弹 Parent 指向本机身体，会被当作附着对象，跳过插值并随当前 Δ 平移，见 5.6 勘误。

**实施前列出的失败方式**：

1. 进房时已在场的泪弹被当成刚出生，从身体处滑出。
2. 地址复用或换形态的对象沿用旧的出生状态。
3. 泪弹传送或不连续（cut）后仍带着出生偏移。
4. 找不到泪弹出生时刻的身体位置（Body 样本环太短、身体刚换地址），偏移算错。
5. 偏移异常大（身体传送、换房后的第一帧），泪弹横穿屏幕。
6. 显示时间早于泪弹第一份样本（Before）时，泪弹停在出生点，偏移衰减把它往回拖，看起来先倒退再飞出。
7. 出生偏移混进 7.2 外推融合的“上一帧显示值”，被重复计入。
8. 插值开关关闭或 Host 暂停恢复后残留偏移。
9. 跟班、其他玩家发出的泪弹被误融合。

**实现**（`client_motion_overlay.cpp`、`client_motion_overlay_native.cpp`）：

- 采集：`ClientMotionEntity` 新增 `spawner`，即 SpawnerEntity `Entity+0x3C8` 的地址，只与本机身体地址比较、不解引用。Spawner 引用随 Tear 平铺记录的引用槽安装。类型 2 不再按 Parent 判定附着（失败方式 9 的一部分）。
- 出生判定：本场景第二次及以后的 World 采样中才出现的泪弹记为 newborn（失败方式 1）。新建或身份重置时重新判定（2）。第一份权威样本记为出生样本 `birth`。cut 时撤销 newborn 和偏移（3）。
- 身体样本环：每个玩家身体保存 32 份 Body 权威样本（约 0.3—0.5s），按地址和身份作键，换场景时清空。
- 首次显示时判定一次：Spawner 必须是本机控制组的身体，跟班或其他玩家的泪弹不融合（9）。偏移 = 身体本帧显示位置（预测中为权威＋Δ，否则为权威值）− 身体在 `birth.h` 的权威位置，后者在样本环内插值。超出样本环时取端点，计 `birth_clamped`；查不到时不融合，计 `birth_no_body`（4）。偏移超过 3 格不融合，计 `birth_dropped`（5）。
- 衰减：从首次显示起 150ms 线性衰减到 0。融合期内若求值落在 Before，沿第一份样本的速度向回推，最多 12h，计 `birth_back`。泪弹因此从身体处连续飞出，不在出生点停住（6）。
- 外推融合记录的 `shown` 不含出生偏移，出生偏移在其后叠加（7）。插值关闭时清空 newborn 与偏移（8）。暂停时 T_w 不动，衰减按本地时钟照常进行，恢复后不残留。
- 开关：`config.json` 的 `motion.tear_birth`，缺省 true，属 P9 本机开关，不进入协商。状态命令输出 `motion_tear_birth`。
- 诊断：`stream.motion.tear_birth`、`birth_fusions`、`birth_dropped`、`birth_no_body`、`birth_clamped`、`birth_back`、`birth_offset_units_*`（出生偏移大小的直方图，单位为世界单位）。

**已知限制**：

- 只修正出生位置，按键到看见泪弹的延迟不变。消除延迟需要独立精灵预测（2.5 记录的 isaac-lan 做法），属于扩大预测范围，另议。
- 衰减期内，泪弹从“相对显示身体”的轨迹回到权威轨迹。持续横移射击时，泪弹在飞行前约 150ms 内会有一段侧向回收。
- 跟班（如 Incubus）发出的泪弹不融合。环绕跟班本身随 Δ 平移，它的泪弹仍从权威位置出生。
- 原版泪弹的 Parent 是否为玩家未在 J273 中核实，只是改为不依赖它。

**第 15 步验收**：客机原地射击与横向、纵向移动射击，看泪弹是否从身体处射出、弹道是否平顺。读数看 `birth_fusions` 是否随射击增长，`birth_no_body`、`birth_dropped` 是否接近 0，`birth_offset_units_p95` 是否与“移速 × 时间差”相符。开关 `tear_birth` 关闭后恢复原表现。

### 11.4 降低输入提前量：时序链换高精度钟（2026-11-20，仅编译，未运行）

**起因**：出生融合实施后，用户反馈移动方向与射击方向垂直时弹道仍怪。根因是本机身体（T_p）与本机泪弹（T_w）之间的时间差，其中最大一块是输入提前量，实测 p50 为 7 tick（约 117ms）。用户决定直接降低提前量。

**提前量的组成**（`client.cpp` InputTiming）：目标 = server_tick + ceil((本地经过 + RTT + 发布年龄 + 不确定度) × 节拍) + `input_lead_ticks`(2)。不确定度原为固定 64ms，即 4 × GetTickCount64 的 16ms 量化（`live.cpp` Timing），约 4 tick，是提前量中最大的一项。

**修改**：新增 `net/timing_clock.h` 的 `TimingClockMs()`（steady_clock，MSVC 上即 QPC，截断到毫秒）。输入时序链的全部时刻改用它：
- Host：tick 提交时刻 `committed_sample_ms`（`tick.cpp`）及其缺省值（`peer.cpp`）、Roster 的 `server_send_ms`、TickProgress 的 `send_ms`、收到客机控制消息的 `echo_server_ms`；
- 客机：控制消息 `sent_ms`（回显为 `echo_client_ms`）、收到 Roster／TickProgress 的 `received_ms`、计算目标时的“现在”。

这些值只在同一进程内相减，不跨机比较绝对值，线格式不变。不确定度改为 4 × 1ms = 4ms。矛盾拒绝阈值（Host 持有时长比客机往返还长）保留原 32ms，只作健全性检查。发送节奏、超时、心跳等其他用途仍用 GetTickCount64，不在本次范围。`input_lead_ticks=2` 不变，它覆盖 Host 侧排队与准入。

**预期**：同机或局域网下，“本地经过＋RTT＋发布年龄”约 20—25ms，提前量约 4 tick（约 67ms），比原来少约 3 tick（约 50ms）。本机身体预测领先量、泪弹出生偏移、对账重放长度都随之减小。

**风险**：
- 余量变小后，网络抖动或 Host 主线程卡顿可能让命令迟到。迟到的命令被 Host 记为 Expired，该 tick 按中性输入处理，表现为预测对账偏差。观察口是 Host 的 `processed_late` 与客机的 `predict_misses`、`predict_neutral_ticks`。若迟到明显增多，再加按迟到率自适应的余量（阶段 4 其余部分）。
- Host 与客机必须同为本版本。若一端仍用 GetTickCount64，其 16ms 量化会被低估，输入会迟到。本改动不改布局版本，混用旧包时握手不会拒绝，部署时须两端一起更新。

**第 15 步验收**：读 `stream.latency.lead_ticks_*`（期望 p50 降到 4 左右）、`timing_uncertainty_ms`（期望 4）、Host `processed_on_time`／`processed_late`（迟到率应仍接近 0），并复看移动射击弹道。

## 13. 未证实与风险

- 第 1.1 节的延迟分解是推算，阶段 0 的计时（已实现，未运行）会给出实测值。
- 对账重放所需的 ControlMovement 内部状态（滑行计数 `+0x1650` 等）没有布局条目，冰面房间重放起点有系统误差（RE-P3 第 4 节）。
- 本地移动计算能否达到“同机几乎无纠正”取决于 RE-P1 的还原精度；Isaac 的移动含较多角色、道具特例，M-a 复刻存在长期维护成本。
- 覆盖层假设 Render 期间不会删除或重建对象，需要 RE-P4 一并确认。
- 预测之后，本机身体在时间上领先敌弹约“往返＋D”；网络延迟高时，屏幕上躲开的子弹在 Host 上可能命中。这是无延迟补偿时的固有代价，只能靠压低 D 和 P6 开关缓解。
