## 2. 低血周期闪烁与护盾资格

### 2.1 低血周期闪烁

本次静态复读J273 `832C10`：在正常HUD生产分支，先按红心、永恒心、魂心、骨心的原生求和判定是否等于1，再排除Holy Mantle显示资格；GameFrame对45取余，前10个相位以整数式`255 * (9 - phase) / 9`产生强度，其余为0。这是原生判定单位，不将其改写成所有角色统一的“半颗红心”。采样／应用阶段必须与实际HUD边界一致，不用Client渲染帧或墙钟替代。

当前P2不传EternalHearts原值，24心显示也不能证明全部健康原值。后续布局采用最小`critical_health`判定投影，表达上述原生健康求和是否等于1；已有可证明等价的完整健康输入可以直接派生这一投影，不能猜缺失永恒心为0。本次不为本地闪烁恢复完整健康生产系统，也不改变逐心格的现有同步职责。

Client使用同身体、同目标的`critical_health`、P8派生护盾与GameFrame计算强度；撤销`low_health_flash`逐帧强度下行及Host原始缓存相等要求。冻结／恢复按明确的显示更新资格与已提交相位处理，不能用网络到包次数推进。最小投影、显示更新序号与最后有效GameFrame已在布局70的435入源；正常来源接线仍待第10步，不能据schema存在宣称已采到这些输入。

### 2.2 Holy Mantle显示资格

J273 `832C10 → 90A490`：外层`disabled`为true时查询为false；否则按顺序寻找配置类别1／3／4且ID313的条目，存在即true。此查询不以库存持有313替代，也不擅自改成`count > 0`或跨类别合并。当前P8已经表达禁用标志与有序效果配置身份，纯值adapter复用它们，不再重复下发`holy_mantle_visible`。

正常HUD更新时用同身体P8求值；暂停／转场等不更新分支须保持相应冻结／重建语义，不把任意P8到达当作一次原生HUD更新。无完整效果或明确更新资格时是依赖缺失，不能默认无护盾。布局70以435的mantle_source_revision指定准确P8输入；当前或已提交快照不能满足时，由条件历史视图436随同原目标补齐，不能在冷连接冻结期间拿任意当前P8代替。这里只派生显示资格，不添加／移除护盾、不运行效果Update或伤害裁决。

三色触发闪烁的red／soul／gold倒计时、心格flash_type、消退与逐心格动画仍按原合同同步；本次不将它们改成“根据相邻收到的生命值猜事件”。

## 3. 普通图标、材料队列与保留的特殊结果

- **普通主动**：复用P4的item、charge、battery_charge、sub_charge、partial_charge、VarData及实际需要的P2／P3／P8状态。本地配置／图像owner提供已声明的普通静态图标映射，图像就绪后缓存；不传普通图标的重复Image选择。当前充能值照常安装，不在Client推进道具充能、Use或EvaluateItems。
- **普通饰品**：复用P3两槽身份与黄金位，本地准备普通图像、生成黄金外观并缓存图像非透明范围形成的中心；不重复下发普通图标的Image与draw_center。图像／资源代次变化使缓存失效，不能只按数值ID长期复用旧图。
- **普通范围须具名**：后续实现登记可由已有状态与本地资源唯一确定的原版普通映射；不能以“正ID”“有配置路径”直接把所有用途标成普通。无法满足该确定映射的必要用途，继续取Host真实特殊选择／资源，不误用普通图兜底。
- **特殊结果保留**：特殊／负visual_id、特殊实际图像、book_image、主动charge_flash、尚不能由现有状态推导的饰品tint_override_source及特殊外观继续由Host表达。纯本地图标缓存失败不改Host选择为Null，不回退传图像像素。
- **材料与队列**：P3的八材料、六便便法术槽为唯一有序数据源，Client只查本地固定显示映射并绘制；不按当前counts重排，也不重复传每格最终Sprite。实际合成输出身份／图像、里以撒等特殊库存的有序显示列表仍由Host提供，不重新运行合成随机、选池或玩法查询。
- **口袋未整体迁移**：四Pocket状态、药丸未知／已识别及身体相关结果、当前专用显示合同不因普通主动图标本地化而自动删除。口袋主动只复用已明确对应的主动槽；ActiveSlot+1不能当道具ID。

完整生命栏、有序InventoryVisual／History列表、特殊图像与上述剩余相位均仍是必要输入。该决定不恢复原始获得史、隐藏保存体、药丸随机映射或全部Player属性。

## 4. Drop渐变与显示时钟

保持原版按实际身体消费Drop产生显示的语义，不新增“所有人跟随本端未确认按键”或玩法预测。后续Host提供经过同一scheduler、暂停／输入屏蔽与消费规则后的Drop持续状态；身体／组及绑定代次必须明确，不能发送物理键盘状态或在Client读取原版设备／Online状态补值。

Client自有owner按有效HUD显示更新执行`held ? min(value + 0.25, 1) : max(value - 0.25, 0)`。到包频率、渲染频率、墙钟与Authority tick均不能未经核对直接当作HUD更新次数；使用已核的显示更新锚点，暂停／loading／屏蔽按其实际规则处理。显示时钟元数据不构成第三条确认序列，仍依world／body目标提交。

初建／冷连接／重连／恢复必须取得当前有效Drop状态及初始化所需的相位／锚点；不能仅从当前held猜Host此前已推进几次。稳定期间只按驱动变化和必要锚点发布，不再逐帧同步`drop_display_scale`浮点结果。用于初始化／纠正的有限相位是驱动合同的一部分，不能据此重新规定逐帧结果必发。

切房／换形／绑定退休时按实际scope／身体use撤销不相容驱动和缓存；不把旧held用于新身体。Host输入不因显示等待、资源失败或Client渐变而改变；Client仅更新自有显示值，不调用Drop交互或物品丢弃逻辑。布局70的435及HudClockCapture已登记实际更新计数、held、更新后有限相位与锚点；正常消费来源及冷连接／恢复装配仍待接线，详见实施说明。

## 5. 基础属性格式化与多人排版

### 5.1 基础属性格式化

范围仅为移速、射速、伤害、射程、弹速、幸运六项基础显示值的数值格式、字体、位置及排版。继续消费Host已正常产生的StatHUD最终`value`；该value已经是对应显示单位，不重复执行射速／射程换算。不因此恢复P1六项Player玩法属性、倍率／历史、CacheFlags或EvaluateItems，也不调用概率生产器。

StatHUD的`delta`／`countdown`、合并概率显示方式、恶魔／天使／星象房结果与Host显示资格保持现有同步职责。不能从相邻网络快照猜完整属性变化历史，不能用访客进度代替Host星象房资格。各端本地字体、显示偏好和布局作用于同一权威数值，不要求字体缓存像素相等。

### 5.2 多人HUD排版

复用已提交P7、participant／control-group、active_anchors、真实身体关系，以及仍有必要的显示角色／顺序；本地计算HUD位置、缩放、行列、紧凑布局、History可见前缀和视口裁剪。不得额外同步Host绝对屏幕位置或原生HUD槽号来代替这些规则。

各端详细HUD继续默认跟随本端控制组；其他参与者公共HUD完整。Jacob／Esau保留双身体，Forgotten／Soul等保留必要关联健康显示，备用／存储体不因存在就自动可见。控制活动资格、roster顺序和显示顺序各有语义，不能盲目互代。已有结构能唯一推出的重复归属不再另发；仍不能唯一确定的显示身体选择、roles、display_order继续由Host提供必要投影。

NO_HUD、有效诅咒、Host world显示资格和必要资源仍施加于本地布局；个人偏好不删除其他人的必要源。`ControlGroupHudSelection`并非整条默认删除，哪些元素可由结构推出须在第9步明确。不得为“本地玩家”改PlayerIndex、ControllerIndex、roster或调用原版Online本地性判断。

## 6. 依赖、准备与提交

本地生成仍有输入、资源与生命周期依赖。第12步候选须明确每用途是“本地派生”还是“保留Host结果”，并校验同身体／组、use/shape、来源修订、拓扑和精确资源；不能既要求已撤销缓存必到，又把真实缺输入当成无需等待。

第13步在目标发布前准备本地图标／中心／文字及显示owner，失败不得用旧身体缓存或默认值确认新目标。需主线程／GPU的工作按已有owner和预算执行，后台只持自有纯值；成功提交后才ACK，后续渐变只维护已提交显示实例。原子范围、world／body窄依赖、原始joint确认和资源ready规则不变。

本地缓存键包含实际用途、subject/use/shape、必要配置／图像资源代次及拓扑；相同ID不表示相同图像或跨代同一实例。退休等待实际writer／draw借用退出后清理，不以撤销逻辑候选代替原生排空。普通与特殊结果同批变化时不得产生半个新HUD。
