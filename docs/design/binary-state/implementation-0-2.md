# 第 0—2 步实现说明

日期：2026-11-08。对应 [第 0 步](0-baseline.md)、[第 1 步](1-layout-source.md)、[第 2 步](2-base-types.md)。本次没有启动游戏或执行测试；第 15 步仍是整个重构的唯一统一整体验收。

## 实现范围

第 0 步复读现行规范、独立工程入口和六份旧文档顶部的替代说明。保留开始前已有的计划修订及 `world_layout.json` 尺寸更正，没有提交、回退或覆盖既有工作，也没有续跑旧 tx-04-21 的 E2E。

第 1 步的唯一布局源位于 `mod/binding/state/`。沿用 JSON；`version.json` 记录整数版本和域清单，源修订手工递增，`schema.json` 与生成器共同约束结构和跨类型语义。生成器作为普通 CMake 构建命令执行，一次生成四份 `.inc` 和每个类型的两类单行表格。首批为 14 种基础类型，加 Entity/Effect 生成链种子，共 18 个展开布局。

- 原生范围展开继承后必须逐字节覆盖对象范围；未知区不自动补成填充。
- 原生归属表和 C++ `NativeRanges` 递归展开内嵌类型；父字段位置证据和子字段证据一起保留，可信状态取两者较弱项。ANM2 内两份 AnimationState 的本地指针、容器和未知区不能被整个标为“状态”，其六个未知字节也计入父对象，供第 15 步探测。
- 状态字段恰好归入一个块，父块固定在前，布局最多 32 块；空预留块必须显式声明。
- 只有同块、原生与状态偏移均连续的直接状态字段合并。复杂嵌套、容器、换算、引用、资源和未知区都会断开。
- 纯值类型的状态顺序必须与原生成员顺序相同；复杂类型递归投影，不允许把容器或指针改名为裸字节复制。
- 嵌套状态的子块可以分别投影到父类型不同块。原生范围只声明一次，全部子块必须各出现一次，避免为 Entity 的 E4/E5/E6 重抄 ANM2 字节事实或把三部分绑在同一变化块里。
- 字段的浮点有限值、布尔、范围和枚举检查生成到 Client 校验表。引用声明目标成员空间，资源声明资源表，容器声明元素、步长、上限及计数来源。
- 变体臂要求形态选择字段及互斥取值集合，每个臂展开后再次检查全覆盖和块归属。
- 公开成员检查只针对已接管的 owner。不能把尚未接管的跨域成员当作已覆盖，更不能伪造“派生”或“权威”以通过生成。

`isaac_cs_state` 是不依赖 SDK、Lua 和 JSON 的 C++20 静态库。生成表通过只读视图提供布局、字段、块、复制区间、校验、Client 数字索引分派、变体选择和公开成员回映射。每个布局记录表切片起点与数量，后续采集不必扫描整个目录。

第 2 步的共用设施位于 `mod/src/state/nested.*`：

- `ReadWindow` 要求实际 owner 线程及当前 generation；读前、读后检查窗口，每个容器头与有效负载各读取一次。实际 ordinary/PlayerPost 见证由第 10 步接入。
- vector 检查三指针次序、元素对齐与数量上限；string 区分 SSO 与堆存储；数组支持相邻计数或具名 owner 计数。`Read*Into` 写入调用方预分配的采集区，缓冲不足时报缺口，不在正式热路径逐对象分配 vector。损坏、越界、读取失败均保留字段路径，不能截断或补空。
- 返回的原生元素区只用于当前主线程递归投影，不能直接发送。线上元素为 `u16 count + payload`，不发送容器头或字符串结尾零。`EncodeElementsInto` 同样使用预分配区，允许 payload 已在同一缓冲中，先移动负载再写计数头。
- Client 容器重建经过 `Begin / Element / Commit / Abort` 的原生 owner 接口，全部准备成功再提交，失败清理临时候选。具体游戏分配器及写入路径由第 13 步各 owner 接线。
- 引用按当前成员表转为 `u16` 序号，Null 为 `0xFFFF`，找不到目标时报具名缺口。
- `ResourceTable` 在一个 epoch 内只追加，保留空序号，不重绑旧序号；可靠表安装先准备完整候选，再原子替换。具体可靠资源消息和帧依赖由第 9、11、12 步接线。
- `anchors.h` 实现模 2^32 的到期帧换算，避免负计数及回绕产生有符号溢出；展示时钟始终来自最近已应用的 world 帧。

首批 `entity-effect.json` 使用已核字段展示继承、FX0—FX2 及基础/TearFlags/GridDesc 臂。Entity 公共字节归属和完整 Effect 臂属于第 3、4 步，本次保留未知，不宣称其完整。旧生成器和运行采集路径继续保留，正式接线及退役分别属于第 10—14 步。

## 必要逆向与主审

必要逆向由用户指定的 GPT-6 Luna（max）子智能体进行，事实材料见 [基础类型证据](base-types-evidence.md)。主智能体独立读取原始指令和官方源码，接受结论前区分静态事实、推导和未知。

已经主审的关键结论（下面均为 J273 VA，imagebase 为 `0x400000`，RVA 等于 VA 减 imagebase）：

- `0x404390`：`0x4043EF` 取 `AnimationState+0x8`，`0x4043F6` 写其中单层选择器，再调用 `0x404030`。公开 LayerID 先经当前 `AnimationData+0x38` 的映射转换为内部层索引，并与 `AnimationData+0x1C` 比较。因此选择器不能只由总帧号派生，读取长度也不能直接使用 Sprite 总层数。
- `0x4040B0`：`0x4040CE` 比较当前动画 `+0x24` 的空层数，`0x4040EA` 取状态 `+0xC` 数组，`0x40411A` 写选择器。空层选择器同样是独立状态。
- `0x9C4EB0`：`0x9C4F10` 写 `Weapon+0x40`，`0x9C4F58` 写 `+0x18` 的 1.0。SDK 的 `0x40` 无法作为实际对象完整范围，构造足迹也不能擅自等同所有动态武器的分配大小。
- 官方 `REPENTOGON-1.1.3/repentogon/Patches/Anm2Extras.cpp:42—98,170—235`：自定义 shader 的路径与指针在 `anm2_extras` 旁表中，按 Sprite 和 LayerID 区分；Reset/destructor 删除对应条目。它们不是 J273 对象中的疑似填充。原生扩展状态必须单列来源，不能复用 Lua getter 热路径，也不能把它冒充为 J273 字节。
- `0x863B30`：`0x863B93/0x863C4E` 将偏移 `0x18` 写入属性闭包，`0x863BB9` 以 `PartialCharge` 注册；配合 `0x8A4558/0x8A45CC` 的 `movss` 读写，确认实际 f32，不能沿用 SDK int。
- `0x7DF4A0/0x7DF5B0`：SetSeed 写 seed 和三个 shift，Next 使用三个 shift 更新 seed，接受 RNG 的 16B 权威归属；不产生发送块。
- `0x858760`：先从旧 Entity `+0x3CC` 引用集合摘除自身，再更新引用并加入新集合。Client 必须复用引用 owner，不能把网络字节直接写成原生地址。
- `0x406710/0x4067B0`：事件查询分别取状态 `+0x18/+0x1C` 掩码，接受两段 i32 状态。
- `0x9C4E60` 是 `fldz; ret`，基类最大蓄力为零；`0x9C5090` 在 owner 条件之外还用浮点指令读取 `+0x28/+0x2C`，不能只按基类字段派生全部武器公开查询。
- `0x9E5BC0` 直接对 Vector 两分量插值；`0x402760/0x67E940` 确认 ColorMod 的 11 个 f32 及 tint/colorize/offset 的 4/4/3 分组。`0x673619` 读取 BitSet128 值参数 16B，`0x67361D` 原样写到 Tear `+0x428`，接受四字纯值布局。
- `0x4041A0` 在 `0x4041B2/0x404239` 以 f32 读写动画帧，普通事件位在 `0x4041FE` 清零；`0x4099D4/0x4099E9` 确认 defaultName 字符串写入目标 `+0x18`。
- KColor `+0x10` 已从推断的 `opaque32` 纠正为 u32 `color_space`。`0x9E37B0/0x9E39F0/0x9E3BA0` 直接确认 RGB/sRGB/HSL 标签 0/1/2；`0x9E3EB0` 是条件转换成功后写回 1 的精确指令。当前安装校验只接受已核标签，其他值报未支持缺口；未把这三项冒充全程序全部合法值。
- Weapon RTTI 首版误把字符串起点 `0xBD1220` 当成 TypeDescriptor。主审回读 header、完整装饰名和 vtable `0xB31C64` 前的 COL 指针：COL `0xB452C8+0xC` 实际指向 `0xBD1218`。已修为 RVA `0x7D1218`。基类虚槽 10 的 `0x9C4E70` 只返回零，不能据此将 `+0x8` 认成主实体。
- Effect 池 `0x6EEE60` 在 `0x6EEE9B` 传入步长 `0x4C0`、`0x6EEE96` 传入容量 `0x400`，构造器 `0x5CCEAF` 写 Effect 虚表；TD `0xBD1270` 后 `+8` 的装饰名与源一致，接受首批 Effect 范围和类型身份。
- TemporaryEffect 普通新增在 `0x90A194` 将尾字置零，但通用插入 `0x90A0D0/0x90A0D3` 复制完整 16B。尾字用途仍不明，不能凭常见零值归为填充，继续列为未知。

主审还从官方 `LayerState.zhl` 确认 `SetSpriteSheet` 不修改路径串，因此实际 Image 选择单列，当前名字到可重建资源身份的唯一性保持推断。`ANM2.loaded` 和 `LayerState.sprite_sheet_loaded` 保守纳入布尔状态，不以“本地缓存”名称省略公开/表现值。BlendMode 的合法枚举来自 `Global.zhl:3340—3362`：方程 0—4，因子 0—9。ANM2 状态按外观、动画、图层分三块，默认动画名作为有界字符串保留。

## 保留的未决与后续归属

14 种基础类型已覆盖各自声明的原生范围（Weapon 仅已核基类前缀），所有范围均有归属和证据。按类型分别展开后有 47B 显式未知区，其中 ANM2 为 14B（含两份内嵌动画各 3B），具体偏移见[第 2 步末节](2-base-types.md#未决问题)。另外的 SDK 声明和推断也保持原标签，没有提升为已核。生成的 `complete` 仅描述原生字节事实，不能代表同步或原版全部取值的验收。

未知区的静态研究及第 15 步未知区探测继续保留。具体动态 Weapon 属于第 5 步；实际 Image 身份、shader 旁表及资源原生接线属于第 8 步；可靠资源表线格式属于第 9 步；实际采集窗口与原生容器 owner 分别由第 10、13 步接线。当前公共目录完整接管 Vector、Color、KColor、BlendMode、ColorParams、ActiveItemDesc、TemporaryEffect 七个 owner；Sprite、LayerState、Weapon 的未闭合项没有伪造成派生或权威来通过生成。

## 构建与实际边界

已执行普通 Release / Win32 / v143 构建，`ISAACCS_BUILD_E2E_TOOLS=OFF`。新 `isaac_cs_state` 静态库与完整 `zhlIsaacCS` DLL 的编译、链接通过；生成器在该构建中产出四份代码表和布局文档。新增基础库没有编译警告；完整目标仍显示 SDK 既有的转换、未用参数、遮蔽和 ASMPatch 析构警告，本次没有改 SDK。

最终布局版本为 **8**；每轮布局源修订均手工递增版本，主审的 RTTI 纠错与嵌套原生归属展开也已纳入最终重新生成与编译。版本 8 来自提交前的静态审阅：EntityEffect `gap_430`、`gap_440` 实际各 16 字节，类型标签由 `bytes[32]` 更正为 `bytes[16]`；字节范围、未知计数和线上布局不变，修正后只重新构建了 `isaac_cs_state` 以更新生成表。

首次 `/m:4` 构建在 core 输出后没有继续进展，已主动取消，没有将该次算作通过。随后用 `/m:1 /nr:false` 完成基础库与完整 DLL；最后的无分配采集接口修改后再次完成完整 DLL 编译/链接。没有添加或执行单元测试、独立校验脚本、probe、E2E、游戏注入、部署或实机操作。正常构建输出仍在 `build/repentogon` / `out/repentogon`，没有另外归档 artifact。

第 9—14 步尚未实施，因此这里的表和共用设施不表示新的二进制同步已经替换现有运行路径。原始 E02 失败及 E03—E26 未执行的事实保持不变。
