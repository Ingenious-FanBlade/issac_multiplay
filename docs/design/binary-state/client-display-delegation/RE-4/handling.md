# RE-4：风险处理与调度交接

返回：[成果总览](README.md)。以下为 `DESIGN`，依据[消费者证据](frame-consumers.md)和 RE-3；没有修改产品代码或测试。保持帧号方案B与 Q8，不为解决显示相位而改变Host帧号、Host锚点或原版Online状态。

## 1. 去重按执行职责，而非所有工作共用 F

| 职责 | 调度／去重依据 | F不变／跳跃时 |
| --- | --- | --- |
| world安装／ACK | 接受层的真实事务、版本与代次 | 有效新事务即使F相同也处理；重复包不重复安装。F不是网络事务ID |
| 本地30Hz显示批次 | Client本地 M偶数与当前用途帧；在所选分支每周期至多一次 | F停住时仍可运行；跳F不补跑多次。不能把每份到包／每次Render当新批次 |
| 相机阶段 | 同一本地Manager周期内一次，使用本机M奇偶与CameraStyle | 按Host暂停和已有转场例外执行；F停住不等同于已暂停，也不连续调用两个相机入口 |
| Q8标量安装 | 成功world事务及当前值变化 | 不本地减一／趋近；变脏值更新与阈值补做同批完成 |
| 周期HUD请求 | 同代次F前进跨过30边界，或显式显示输入变脏 | 合并为一次必要请求，不因相同F重设countdown |
| 原生Render | 既有原生绘制调用／有效用途作用域 | 不以F相同为由丢整次Render；Render不负责再调用HUD／FX／Sprite Update |
| 显示音效／表现事件 | 本地显示调用资格与Q7，或已接受的事件序号 | 不能拿SFX内部FrameDelay或F作为跨来源去重规则 |

保留 RE-3 的先后关系：本周期先完成安装／注入／Q8阈值补做，再运行本地30Hz分支和相机；本地M由唯一owner在既定阶段推进，Render消费对应半帧相位。用途帧防重入／取消／退出清理仍由既有分派负责，Hook启动安装后常驻。

同一个M不能因到来第二份world再跑一遍HUD／FX。应在显示消费者执行前收拢／提交本周期目标；已经开始消费后，把后续安装留到下一安全周期。缓存／冷构建确需同M刷新时，执行明确的缓存维护，不把维护冒充第二次显示批次。重建后的资格按新的生命周期建立，不把旧M数值直接当已经执行过。

RE-1 的提前返回分支补遗仍待完成：这些节奏约束不意味着暂停、开场等待、ItemOverlay或GameOver都运行普通分支。RE-9继续决定转场阶段及目标等待处，不能用F冻结代替转场等待协议。

## 2. 周期 HUD 刷新

将旧“F%30==0就请求”改为具名本地显示请求维护：

1. 仅对接受层已判定为同代次普通向前推进的F，识别上次已处理F至本次F之间是否跨过30帧边界。一次跨过多个周期也只需一个最新状态刷新，不循环调用原生链。
2. 首次绑定／换房／合法回退／重建时重置该本地周期记录，并按实际依赖标脏。不要把无符号大差值解释为几百万次周期；正常编码的模2^32运算与生命周期判断分开。
3. 请求只按原生语义写 HUD type=1、countdown=2，**type=2不覆盖**。请求可合并／延后，实际何时消费仍用原生 consumed标志与 HUD更新，不伪造已绘制事实。
4. 同F不重新提出同一周期请求；但库存、Player显示输入、DisplayFlags／地图缓存等真实变脏不受这个去重限制。type=2期间仍有脏项时保留一个待处理请求，之后合并提出，不反复写countdown。

这一记录只是显示请求的处理历史，不是另一套展示时钟，不替换 F／M。F的读值、锚点还原与停止语义保持方案B。

## 3. 缓存、年龄阈值与历史画面

### 平均位置缓存

- 安装实际Player roster、位置／关系后，才进入依赖平均位置的FX／相机／绘制查询。正常周期 M自然推进时，原生缓存会因戳不同重算。
- 冷绑定、M重置／复用、同M发生有效目标或roster更换时，使用已核平均位置 helper的 useCache=false 路径作一次具名维护，刷新该M的缓存；后续true消费者自然复用。
- helper采用真实当前PlayerManager与输出Vector、bool，两栈word／ret8；若后续建立绑定，按已核caller与统一具名入口完成，不凭伪代码补隐藏参数。
- 不直接伪造 `0xBD01E8`／缓存坐标，不创建占位Player，不多调 `FXLayers::Update(true)`“顺便刷新”，后者还会推进pose／vein／Sprite并改变平均位置模式。

### StatHUD与其他年龄阈值

- E是Host实体年龄，不能用来判断本地HUD是否已经看过该实体。晚加入／重新绑定本地StatHUD槽时，应由缓存owner对已安装当前属性建立初值：current／previous保持一致，delta与提示计时中性，然后正常接受后续变化。
- 原生单值helper揭示了提示历史字段的用途，但SDK未提供完整字段／普通float ABI；后续优先既有原生初始化路径，无适用API时用具名缓存writer，不调用Player Update／EvaluateItems，也不临时把E改成0。
- 在前进的F中，NPC的 E>1、光照的 E<7／10、FX的clamp(R/30)直接求目标表现。跳过短窗不意味着要补生成或补跑Render；真正必须到达的瞬时演出按既定状态／事件承接。

### 本地历史 surface

- 保留Game::Render原生年龄30分支及本地采样随机；它不是一次性玩法动作。停在30可能反复捕获，跳过30可能不捕获，按Q4接受本地历史采样差异，不把判断改成 >=30。
- 首次本地显示或历史surface失效时，资源owner必须准备本地存储／有效上下文；需要首份历史时，可在正确构建阶段提出一次本地刷新请求。已核 byte `Game+0x25AB8=0xFF` 会让下一次真实Render进入捕获并回置1，可作为具名本地维护的依据；本次未实现该writer。
- 不从Host复制历史图像／标记，不因每份world都强制刷新，不为捕获而调用ShowHallucination或伪造R=30。普通切房保留原生历史选择，只有资源／生命周期失效才按owner重新建立。

## 4. 停顿、跳帧与原生随机

- **仅网络停包**：F／Host锚点／Q8当前值保持；本地消息、地图、FX和符合条件的相机继续。Camera在固定F的 `%3` 分支内仍可每本地周期取随机，这是Q4外观随机，不以F相同去重其随机调用，也不把结果回传Host。
- **Host暂停状态已应用**：F保持；相机按已定暂停条件／特定转场例外；其他显示入口的分支资格按RE-1补遗。不从“几轮没有新F”自行推断Host已暂停。
- **Q8震屏结束**：仅安装已应用的 countdown正数→0 时清本地偏移。停包中旧countdown仍为正，不用墙钟或M替它递减，也不为“看起来该结束”运行GameUpdate。
- **F跳过若干帧**：phase直接跳至目标；TimeCounter／Effect Timeout按RE-3同目标换算，其他原始倒计时按当前合同安装。不会补跑ΔF次Sprite、FX、HUD、物理或规则，避免重复事件／声音／资源操作。
- **合法回退／world重建**：重建本地“已处理周期／缓存／绑定”资格；保持Host原始F／锚点与当前效果值，不强制F全局单调。丢失的旧瞬时事件也不按帧差重造。

Player伤害闪烁等独立计数仍取Host实际采样；F停住并不能让它本地自动前进，F前进也不意味着这个render帧单位计数每次只减一。原生显示是否改变某个已同步字段交RE-5漂移处理，不能由显示相位推导玩法写回权限。

## 5. 第13步修改与第15步覆盖

实施交接：在统一Manager分派加入按本地周期的批次／相机执行记录；实现合并的周期／变脏HUD请求；由实际生命周期owner处理平均位置缓存和StatHUD冷绑定；本地历史资源归资源owner。原始F／B／E安装及到期帧还原按RE-3，不在Render建立FrameBorrow；已有FullSort迁出，不使用原生render_sort的F奇偶渐进。
