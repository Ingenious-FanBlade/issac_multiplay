# world/body 独立消息zstd压缩

2026-11-11，按用户要求仅新增world/body消息的zstd压缩，布局版本 **66**。现有增量粒度、Sprite槽位、动画／音频职责、字段、速率／容量／时间与ACK／恢复语义均保持；不运行测试，第15步唯一统一验收。349布局／2806字段／85条件与公共固定头尺寸不变。

## 实施前列出的失败方式

- 仅取消发送限制，接收route仍拒绝动态压缩；或对仅支持可靠zstd的旧Peer发送动态压缩。
- 压缩上下文依赖前一消息／字典，丢帧后无法独立解码。
- 仅检查压缩大小，解压超过原64KiB；放宽保护或挪可靠通道绕过预算。
- 小包膨胀仍发压缩版，压后大小未进入分片／速率计费；压缩计量误记原文或虚构压缩收益。
- 压缩一条消息却发送原来的长度／codec，缓存未区分协商状态，跨route借用不兼容结果。
- 把动画／音频／字段增量等讨论中的其他方案一并实施。

## 正式行为

- 使用已有Codec::Zstd编号1与现有ICRF／ICSR长度字段。沿用zstd level3、最大8MiB窗口；一条完整逻辑消息一个独立帧，新建无字典上下文，不依赖前条消息。动态消息仍按latest-only承运，不加入ReliableSender。
- 新增可选能力`world-body-zstd-v1`，并要求已有`zstd-v1`共同协商。stream协商结果只在双方均显式支持时保留该新增标志，Host／Client route均记录world_body_zstd；接收端在分配／解压前按授权route检查。缺少能力时world/body沿用原文，Baseline／Context原有压缩行为保持。该可选协商不建立不同binary layout_version间的兼容分支。
- 完整逻辑消息解压后仍最多65536B，包含40B信封，Frame正文仍最多65496B；压缩字节也受原64KiB／64分片等限制。压缩不能让超限原文被接收，不放宽数量、字段访问、缓存、速率或时限。
- 动态压缩结果严格小于原逻辑消息时采用Zstd，否则采用None及原文，释放废弃压缩暂存。None继续按原规则参与合包；Zstd保持完整独立分片，不把压缩体冒充可合包正文。最终包成本仍按实际合包／分片／路径计算，不能用压缩字节下降推导所有小包合包后的总成本一定下降。
- 接收严格检查单个普通zstd帧、完整消费、禁用字典／skippable／拼接多帧、解压长度与窗口；随后照常核信封、route／scope、正文和完整目标。压缩成功不等于可提交或可ACK。

## 实现与所有权

`stream_transport.h/.cpp`新增`CompressWorldBodyInto／DecompressWorldBodyInto`，直接处理自有完整ICSR字节，支持未来二进制Frame接线；函数不构建JSON、不访问游戏。输入／输出禁止重叠，返回span由owner持有，scratch至少容纳zstd compressBound，实际capacity和zstd内部上下文分配仍计原复制池，不增加额度。原文与压缩暂存并存时分别计其真实租约。

当前`EncodeBlob`的WorldDynamic／PlayerFast分支使用相同接口；PublicationSender将协商结果交给既有异步EncodingCache，原缓存键含压缩选择，统计保留实际最终bytes及压缩尝试CPU。`Reassembler`按新授权标志接收动态zstd，并使用同一有界解码接口。Baseline／Context保留原压缩实现，Control／Input不开放压缩。

`StateOrdinarySendLowerBoundFits`现在接受合法的压后实际长度，沿用原decoded保护、原分片／路径计费及world100ms／body50ms必要条件。仍不预估压缩收益，不改变9Mbps／各通道额度或所有容量／时间值。

第11／12步完整StateFrame运行链的接线边界保持；本次不单独启用Kind21或恢复旧Range为二进制兼容格式。当前传输链的动态压缩与未来二进制完整ICSR纯字节接口均已提供，不表示真实原版来源／原生应用已经完成。

## 静态预算与后续验收

版本65账本中的设计负载继续保留“不压缩”条件，不能改成凭空假设的压缩率。以默认48B路径、无额外中继和未计其余内容为例，要满足原单流额度，八身体动画投影3392B逻辑消息须压到≤2272B，稠密运动6416B须≤4544B；这只是临界整数成本，不是实测可达结论。真实比率、压缩CPU与排队年龄、实际合包后的总体收益在第15步统一验收。

未来第15步覆盖：双方／单方能力组合、None回退、丢前一动态消息仍可独立解下一消息、重复／冲突分片、坏压缩体、虚报解压长度、超过64KiB或窗口上限、字典／多帧拒绝、原可靠路径及动态ACK／恢复语义。当前不编写或运行测试。
